# tlipoba

Локальный планировщик билдов Torchlight Infinite с объяснимым расчётом характеристик и урона. Ориентир по возможностям — [Path of Building Community](https://github.com/PathOfBuildingCommunity/PathOfBuilding): состав билда, условия боя, сравнение вариантов и подробный разбор вычислений. Это самостоятельный проект; код Path of Building не переносится.

Первый поддерживаемый срез: **Carino — Zealot of War, Chromatic Shot с переводом физического урона в холод и Tangle, SS14**. Сначала проверяем математику одного билда, затем расширяем поддержку.

English: an independent, local Torchlight Infinite build planner, starting with one Carino build and traceable, evidence-backed damage calculations.

## Начальная основа

- Чистые функции расчёта крита и Lucky, конверсии Physical → Cold, независимых множителей, Tangle и нескольких попаданий
- Группировка дополнительных бонусов по affix, отношения исходного и целевого боевого состояния, броня монстра и отдельная проверка расхождения с замером
- Локальные версионированные факты TLIDB со ссылками на первоисточники и явными ограничениями
- Отделение наблюдаемых показателей персонажа от предположений о цели и состоянии боя
- SQLite с происхождением данных и автономный HTML-отчёт с последовательностью вычислений
- Детерминированные тесты, не требующие игры и подключения к сети

Пока это исследовательская основа калькулятора. Полное восстановление урона из всех предметов, талантов и состояний боя ещё не завершено. Панельный Spell DPS и измерение на манекене — разные наблюдения; совпадение с игровым DPS не заявляется. Контрольный замер служит проверкой, его нельзя использовать для подбора скрытого множителя.

Целевой пользовательский сценарий — автоматический импорт по коду/ID, из файла билда или из открытой игры. Скриншоты и ручное переписывание персонажа не должны быть обязательны. Доступность игрового API пока исследуется; текущий CLI ниже служит разработке и проверке математики.

## Запуск

Требуется Python 3.13 или новее. Расчётное ядро использует стандартную библиотеку Python; установка сторонних библиотек для запуска тестов не нужна.

Пока проверяем проект только локально на Windows. GitHub Actions отключён; облачные раннеры и их минуты не используются. Локальный запуск:

```powershell
C:/Python313/python.exe scripts/test.py
```

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
python -m damage_lab --help
```

Импорт сохранённого пакета без скриншотов и файла ручных показателей:

```powershell
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --output local-reports/import
```

Команда сохраняет доступный состав билда, автоматически извлечённые показатели, их источники и список пробелов в `import.json`, `database.sqlite` и `index.html`. Каталог результата должен быть новым. Если данных для DPS не хватает, импорт показывает это явно и не подставляет вымышленные значения.

Для выбранного наблюдаемого камня можно собрать входы будущего расчёта без ручных статов и боевых параметров:

```powershell
python -m damage_lab inputs --package "ПАПКА_ЭКСПОРТА" --skill "gem[1]" --output local-reports/inputs
```

Alias берётся из отчёта импорта; здесь он приведён для примера. Команда сохраняет точный каталожный lookup на уровне камня, подходящие кандидаты модификаторов и совместно установленные поддержки в JSON, HTML и SQLite. Effective level, активация и полные пулы остаются неизвестными; итоговый DPS пока не вычисляется. [Контракт входов](docs/BUILD_INPUTS.md) описывает проверки и ограничения.

Пакет и точные значения панели можно импортировать одной командой, пока игра работает:

```powershell
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --game-log "ПУТЬ_К_ЖУРНАЛУ/UE_game.log" --output local-reports/import-from-game
```

Промежуточный JSON не требуется. Источник сохраняет хеш и размер прочитанного снимка, даже если журнал продолжает расти. Вместе с девятью основными показателями импортируется доступное пробивание брони; отсутствующее значение не заменяется нулём.

Если новый экспорт содержит `trait-ranks.json`, поля воспоминаний и кандидаты рангов также загружаются автоматически. Отчёт показывает источники и неопределённость; итоговый ранг не выбирается и не применяется к DPS до подтверждения правила.

`import-coverage.json` из новых пакетов автоматически добавляет аудит девяти областей: полученный состав отдельно от неподтверждённых эффектов, активации и идентичности панели. Прочитанные source/guide проверяются по хешам. Это не заявляет полный импорт или точный DPS; [контракт](docs/IMPORT.md) сохраняет эти ограничения.

`build-resolution.json` сохраняет проверку ожидаемого кода и исходного снимка. Совпадение сохранённого кода не подтверждает транспорт, идентичность ответа или свежесть; эти ограничения видны в JSON, SQLite и HTML.

`installed-skills.json` из новых пакетов автоматически переносит наблюдаемые камни и связи групп в SQLite, JSON и HTML. Хеш исходного файла, версии и счётчики проверяются; активация, роль поддержки и effective level остаются неизвестными. Установленные связи не применяются к DPS. [Контракт](docs/SKILL_BUNDLE.md) описывает формат и явные ошибки получения данных.

`static-combat-modifiers.json` автоматически переносит частичный typed ledger вещей и координаты исходных каталогов в JSON, SQLite и HTML. Хеши и счётчики проверяются; неизвестные эффекты остаются пропусками, runtime не подтверждён. Аффиксы не применяются повторно к панели или DPS. [Контракт](docs/STATIC_COMBAT.md) описывает происхождение и ограничения.

Для обычных напечатанных таблиц журнала есть отдельный ограниченный reader `damage_lab.buildlog.snapshot`: он сохраняет лексические значения, элизии, границы событий и хеш прочитанного снимка. Это ещё не полный импорт персонажа; [контракт reader](docs/BUILD_LOG.md) отделяет чтение файла от интерпретации состава.

Состав доступных событий можно получить отдельной командой без пакета и ручных показателей:

```powershell
python -m damage_lab import-log --game-log "ПУТЬ_К_ЖУРНАЛУ/UE_game.log" --output local-reports/log-import
```

Она сохраняет подходящие состояния отдельно в JSON и HTML; последнее не выбирается автоматически и события не объединяются. [Диагностика импорта журнала](docs/LOG_IMPORT.md) описывает выбор одного события, printed-only coverage и оставшиеся пробелы.

Для отдельного сохранённого снимка остаётся двухшаговый вариант:

```powershell
python -m damage_lab.panellog "ПУТЬ_К_ЖУРНАЛУ/UE_game.log" local-data/panel-log.json
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --panel-log local-data/panel-log.json --output local-reports/import-with-stats
```

Сопоставление с серверным Spell DPS проверяет согласованность состояния; личность персонажа этим не подтверждается. При неоднозначности импорт отказывается выбирать запись. [Контракт и ограничения](docs/IMPORT.md) описывают девять поддержанных параметров, точность и источники. Для расчёта `--observations` уже не обязателен, если пакет и журнал содержат все необходимые статы.

Полный пример с вымышленными данными, без игры и аккаунта:

```powershell
python examples/make_fixture.py local-data/example
python -m damage_lab --package local-data/example --observations local-data/example/observations.json --facts damage_lab/data/tlidb-ss14.json --output local-reports/example --basis panel --active 2 --hits 3 --retention 0.2 --resistance 0.23 --taken 0.11 --uptime 0.87
```

Результат: `local-reports/example/index.html`, `calculation.json` и `database.sqlite`. Пример даёт условный DPS **72 066,9153456**. Все входные значения вымышленные; это проверка воспроизводимости арифметики. Каждый запуск требует нового каталога результата и сохраняет предыдущие отчёты.

Проценты в параметрах задаются долями: `0.23` означает 23%. `--retention` — явно выбранная оставшаяся доля каждого следующего попадания; трактовка коэффициента shotgun из игры пока не подтверждена. `--hits` задаёт фактические попадания в одну цель за каст одного Tangle. `--basis panel` использует готовый Spell DPS без повторного применения крита и предметных бонусов. Вариант `--basis hit` считает от среднего некритического удара и дополнительно требует `--lucky` либо `--no-lucky` и `--critical-more`.

Для проверки изменений состояния добавьте `--combat examples/combat.json`, выбрав новый каталог результата. Формат и ограничения описаны в [docs/COMBAT.md](docs/COMBAT.md). Этот файл — вымышленный пример арифметики. Модификаторы сравниваются как `factor(target) / factor(reference)`, поэтому известный бонус, уже включённый в панель, не применяется второй раз. Пробивание брони требует явной эффективности и неподтверждённого порядка применения; режим тиков 30 Hz также включается только как проверяемая гипотеза. Отчёт показывает остаточное расхождение с бенчмарком отдельно от множителей урона.

Приватный экспорт персонажа можно подготовить отдельным локальным инструментом и передать калькулятору как внешний входной файл по справке CLI. Экспортёр и доступ к процессу игры не являются обязательной частью публичного проекта. Не кладите реальные `source.json`, дампы, скриншоты аккаунта и отчёты персонажа в репозиторий. Для примеров и тестов используются синтетические данные.

Первые автоматически извлечённые показатели подхватываются из новых пакетов: Spell DPS и Survival из сохранённого серверного ответа. Для отдельного файла разработчик может задать `--native-stats ФАЙЛ.json`. SHA-256 исходного снимка должен совпасть с пакетом; данные другого билда отклоняются. Происхождение и расхождения с прежними наблюдениями сохраняются. Это частичный импорт: [формат и оставшиеся пробелы](docs/IMPORT.md).

## Как читать результат

Результат должен показывать исходные данные, формулу, применённые множители, условия цели и неизвестные эффекты. Если трактовка механики не подтверждена, она остаётся явным параметром сценария или причиной неполного расчёта. Например, число снарядов не доказывает число попаданий в одну цель, а число созданных Tangle не равно числу прикреплённых.

Факты SS14 находятся в `damage_lab/data/`. Дата проверки и источник относятся к конкретной записи; версия игры и сайт могут расходиться. Неподтверждённые строки таблиц уровней нельзя молча экстраполировать.

Результаты исследования: [существующие калькуляторы](docs/research/existing-calculators.md), [импорт по коду и API](docs/research/build-import-api.md), [формулы Carino и нерешённые вопросы](docs/research/carino-combat-formulas.md). Публичный игровой API для полного импорта пока не подтверждён; декодирование кода в 16 байт само по себе не загружает билд.

[Проверка формулы панели по двум состояниям](docs/research/panel-formula-evidence.md) сужает варианты, но пока не устанавливает полный Spell DPS. Необъяснённое отношение не используется как множитель расчёта.

Статьи встроенной справки исследуются отдельно: [урон и крит](docs/research/help-damage-critical.md), [конверсия и защита](docs/research/help-defense-conversion.md), [рост после уровня 20](docs/research/help-skill-levels.md). Зеркало TLIDB помогает получить тексты автоматически; их версия ещё требует сверки с клиентом.

[Полный реестр Help](docs/research/help-library.md) охватывает 263 адреса: 261 прочитанное тело и два явных пробела источника. Есть офлайн-поиск `python -m damage_lab.helpbook search "drop"` и отдельная [библиотека расчёта ожидаемого дропа](docs/LOOT.md). Прочитанная формула не означает реализованную механику.

[Проверка происхождения состояния](docs/research/import-state-provenance.md) отделяет установленные поддержки от их активации, а именованные статы — от неподтверждённых числовых ID. Эти пробелы сохраняются при автоматическом импорте и не заполняются подгонкой DPS.

[Оценка сохранённого кода билда](docs/research/build-resolution-evidence.md) уточняет недостающий контракт загрузки. [Исследование Tangle](docs/research/carino-damage-gates.md) отделяет специальные cast-time события от неподтверждённого общего наследования параметров.

[Сравнение поддержанных замен](docs/UPGRADES.md) использует общий боевой сценарий и явно заданную цену; неизвестные эффекты ограничивают рейтинг. Команда `python -m damage_lab upgrades --scenario examples/upgrades.json --output local-reports/upgrades-example` сохраняет JSON и HTML вымышленного примера. Подбор реальных вещей и получение рыночных цен ещё требуют адаптеров.

[Расчёт исходного spell hit](docs/RAW_DAMAGE.md) собирает базовый Physical→Cold hit, отдельные flat/increased/more, ожидание крита и скорость до защиты цели. Синтетический пример: `python -m examples.calculate_raw_spell`. Неизвестные source gates блокируют числовой результат; этот блок пока не подключён к полному автоматическому расчёту персонажа.

[Входы из статических модификаторов](docs/LEDGER_INPUTS.md) сохраняют подходящие flat/increased/attribute/speed строки и координаты значений для явно заданных skill tags. Это частичный инвентарь кандидатов: неизвестные эффекты и запрет арифметики сохраняются, готовые суммы персонажа не выводятся.

[Математический оператор роста навыка](docs/SKILL_GROWTH.md) принимает два явно выбранных rates и сохраняет малые приращения без выбора профиля SS14. Он не восстанавливает effective level и не умножает готовый Spell DPS.

[Бонус основных характеристик](docs/MAIN_STATS.md) складывает вклады явно подходящих финальных totals при обязательном выборе ставки и проверке сценарных gates. Неизвестные totals или ratio блокируют factor; native IDs и оператор Lightchaser не угадываются.

[Поля навыка из каталога](docs/SKILL_PROFILE.md) отделяют skill tags от типов урона, сохраняют main stats, stated effectiveness/seconds и проверяют полный reference render диапазона точного уровня. Пакет с `manifest.installedSkillCatalog` автоматически снабжает [профили установленных камней](docs/INSTALLED_PROFILES.md) точными записями каталога с проверкой source/artifact hashes. Lookup уровня камня отделён от неизвестного effective level и не меняет DPS. [Исследование уровня](docs/research/effective-level-bindings.md) сохраняет найденные прибавки и пробелы; [привязки специальных поддержек](docs/research/special-support-bindings.md) отдельно описывают native rolls и каталожные константы.

[Разбор эффектов специальных поддержек](docs/SUPPORT_EFFECTS.md) проверяет полный native ID, собственный tier и точный roll, сохраняя литералы каталога отдельно. Новый пакет с `manifest.installedSupportEffects` автоматически переносит эти кандидаты в SQLite, JSON и оба HTML через [проверку байтов и каталожных координат](docs/SUPPORT_BUNDLE.md). Активация, effective level и grouping остаются неизвестными; кандидаты не масштабируют DPS.

[Кандидаты прибавок к уровням навыков](docs/LEVEL_BUNDLE.md) из `manifest.installedLevelCandidates` проходят проверку байтов, source hash, установленного состава и declared catalog provenance. SQLite, JSON и три HTML отчёта сохраняют собственные роллы, литералы, вычисленные привязки, пробелы рангов и неоднозначные установки. Кандидаты не складываются; effective level и полный DPS остаются неизвестными.

[Боевой слой raw spell](docs/RAW_COMBAT.md) соединяет этот результат с явными Tangle/topology, Cold defence, бронёй, damage taken и uptime. Крит и скорость не считаются повторно; неизвестные inheritance/topology/target gates блокируют полный DPS. Полностью вымышленный пример: `python -m examples.calculate_raw_combat`.

[Сравнение полных боевых замен](docs/COMBAT_UPGRADES.md) пересчитывает каждый rawcombat-сценарий при одной цели и uptime и ранжирует известный положительный прирост по явной цене. Неизвестные эффекты блокируют дельту и рейтинг; автоматического подбора вещей или рыночных цен здесь пока нет.

Команда `python -m damage_lab combat-upgrades --scenario examples/combat_upgrades.json --output local-reports/combat-upgrades-example` сохраняет JSON и самостоятельный HTML этого вымышленного сравнения. Пробелы видны в отчёте; существующие результаты сохраняются.

[Частичный источник из журнала](docs/research/passive-log-import.md) содержит состав некоторых систем, но обрезает таблицы навыков и не печатает таланты или native stats. Он исследуется как дополнительный пассивный адаптер; полного импорта из него пока нет.
