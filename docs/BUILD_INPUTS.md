# Автоматическая подготовка входов модели

`buildinputs.assemble(record, *, skill_alias)` связывает уже импортированные
наблюдения в один отчёт о входах расчёта. Он не читает файлы, не суммирует неполные
пулы и не использует панель или benchmark, чтобы заполнить отсутствующие значения.

`record` проходит `importer.snapshot`: профили, статические строки и эффекты
поддержек повторно проверяются своими validators и должны иметь тот же source SHA.
`skill_alias` — явно выбранный `gem[n]`, где n — положительное число до девяти
цифр. Это предел интерфейса, не максимум игры. Не найденный alias не заменяется
первым камнем, главным слотом или навыком с похожим названием.

Выход `tli-build-input-report-v1` содержит:

- `source_sha256`, четыре false claims и `status=blocked`;
- `selection {alias, basis: explicit_alias, status}`;
- `skill`: безопасный member каталожного lookup либо `null`;
- `modifiers`: результат `ledgerinputs.inputs` для его явно наблюдаемых skill tags
  либо `null`, если нет достаточного контекста;
- `installation {status, members}`: только совместно установленные камни той же
  группы либо неизвестный слой;
- `gaps`, `raw_spell=null`, canonical `record` и фиксированные `assumptions`.

Source record сохранён для повторного вычисления проекций в renderer. Лишние
native/account поля не копируются; известные данные локального импорта остаются
локальными. Выбранный member, modifier rows и installation отделены от record
и исходного объекта.

## Правила связывания

Теги берутся из точного каталожного профиля выбранного камня, а не из имени или
описания. Damage types и reserved scopes не становятся skill tags. Применяется
существующая фильтрация `ledgerinputs`: attack-only строка не становится spell
добавкой; исключённые строки и неполное покрытие сохраняются. Известные пустые
массивы отличаются от неизвестных входов `null`.

Совместная установка проверяется по alias, группе, tab, slot и source path;
известные base ID и gem levels должны согласовываться. Противоречивый слой
получает `installation_context_conflict`, без приписывания чужих эффектов.
Профиль выбранной группы также сверяется с исходным `installed_skills`: alias,
ID, уровень и координаты должны точно совпасть. Противоречие — ошибка входа;
отсутствующий или неизвестный слой даёт `skill_inventory_unavailable` и не
подтверждает выбор профиля.
Совпадение группы не подтверждает активацию поддержки, её применимость к выбранному
навыку или включение в панель.

## Границы расчёта

Этот формат пока не создаёт пригодный для числового `rawspell` сценарий.
Неподтверждёнными остаются effective level, текущий профиль версии, действующая
база, итоговые main attributes, полный crit/cast pool, конверсия, активация
поддержек и боевой контекст. Они перечислены отдельными стабильными gap codes.
Additional-пулы не объединяются по похожему тексту, уровень камня не становится
effective level, неизвестные числа не заменяются нулями или единицами.

Отсутствующий каталог, неизвестный client layer, отсутствующий exact skill ID,
непригодные теги или отсутствующий static ledger дают конкретные причины.
Malformed canonical data и ложные claims остаются ошибками. Limits skill tags
следуют контракту `ledgerinputs`: до 32 различных тегов без типов урона/scopes.

`buildinputreport.render(report)` повторно вызывает assembler по сохранённому
canonical record и alias, сверяет весь JSON и показывает только новый результат.
Подменённые derived поля не принимаются. HTML сохраняет exact decimal strings,
source coordinates, отдельные native rolls/catalog constants и неизвестные
значения; не вычисляет и не рекомендует итоговый DPS.

## Команда без ручных показателей

```powershell
python -m damage_lab inputs --package "ПАПКА_ЭКСПОРТА" --skill "gem[1]" --output local-reports/inputs
```

Alias выбирается из наблюдаемых камней отчёта `import`; `gem[1]` здесь только
пример. Команда не выбирает основной навык и не определяет его по имени.
Нужен новый путь результата. В него атомарно сохраняются `inputs.json`,
`index.html` и `database.sqlite`; существующий результат не перезаписывается.
Пакет читается обычным archiver без файла ручных observations. `--facts`
необязателен: по умолчанию используется локальный `combat-ss14.json`.
Можно передать `--native-stats` и один из `--panel-log`/`--game-log` по контракту
обычного импорта; эти данные не заполняют отсутствующие входы rawspell.

Успешное сохранение диагностического отчёта возвращает код 0 даже при
`status=blocked`: это успех импорта и сборки кандидатов, а не готовность DPS.
Ошибка аргументов, проверки пакета или сохранения возвращает 1 с фиксированным
сообщением без содержимого источника. Частичный собственный staging удаляется,
а уже существующие чужие файлы сохраняются.

Локальные синтетические проверки:

```powershell
python -m unittest discover -s tests -p test_buildinputs.py -v
python -m unittest discover -s tests -p test_buildinputreport.py -v
```
