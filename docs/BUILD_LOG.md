# Офлайн-снимок деревьев обычного лога

`damage_lab.buildlog.snapshot(Path)` читает только явно переданный файл. Формат результата — `tli-build-log-v1`, версия `0.1.2`. Команды CLI, подключения к archive, чтения процесса, интерфейса игры и сети здесь нет.

```python
from pathlib import Path
from damage_lab.buildlog import snapshot

document = snapshot(Path("local-data/saved-example.log"))
```

Это локальный диагностический результат: `status="diagnostic"`, `scope="printed_tree_only"`, `import_complete=false`. Identity, runtime, freshness, выбранный навык и код билда остаются `unknown`. Полнота напечатанного дерева не доказывает полноту импорта. События не объединяются; числа не превращаются в native stats, параметры ServerSource, единицы или эффекты DPS.

## Байты и границы

Файл открывается один раз в binary mode. Начальный `fstat` фиксирует количество байтов; чтение прекращается на этой границе, даже если файл вырос. SHA-256 покрывает **все прочитанные байты этого префикса**: посторонние строки, отклонённые события, CRLF и незавершённый хвост. При уменьшении файла во время чтения результат не возвращается. Это ограниченный снимок префикса, не блокировка файла и не доказательство одновременности всех его записей.

`source` содержит локальный `path`, `sha256`, `kind="ordinary_log"`, `snapshotBytes`, `bytesRead`, `lines`, `ignoredLines`, `oversizedLines`, `retainedEventBytes`, `incompleteFinalLine`. `lines` включает незавершённую последнюю строку, если она есть. `ignoredLines` считает завершённые строки вне распознанных событий; `oversizedLines` считает все физические строки длиннее лимита. `retainedEventBytes` — сумма исходных байтов только успешно разобранных событий, включая их заголовки и CRLF/LF. Размер незавершённого хвоста и его номер находятся в `incompleteFinalLine={line,bytes}`; иначе поле равно null. Номера физических строк начинаются с 1.

Разделитель — LF. Только один CR непосредственно перед LF удаляется как transport framing; второй CR остаётся данными и приводит к отказу грамматики. Исходные байты SHA при этом не меняются.

Каждая завершённая строка, начинающаяся с ASCII `[`, закрывает предыдущее событие, в том числе посторонняя или слишком длинная строка. Новое событие начинается при полном совпадении ASCII header grammar из `logtables.HEADER` либо при таком же заголовке с **одним завершающим ASCII-пробелом после `[Game]`**. Последний вариант — наблюдаемый logging framing: адаптер удаляет ровно этот пробел только из распознанного заголовка перед `parse_event`. Два пробела, табуляция, Unicode-цифры и другие похожие заголовки не принимаются. Тело, значения и колонки не проходят strip или иную нормализацию.

Успешные `events` содержат `{start_line,end_line,boundary,header_trailing_space,tree}`. Границы строк включительные; `boundary` — `next_record` либо `snapshot_boundary`. Bool `header_trailing_space` явно отмечает удалённый framing-пробел; для исходно строгого заголовка он false. `tree` — результат публичного чистого `logtables.parse_event`, включая его отдельный статус `complete`/`elided`, lexical scalar text и неизвестный часовой пояс. Статус `complete` относится только к напечатанной структуре. SHA и лимит байтов события всегда учитывают исходный framing-пробел.

Незавершённая последняя строка никогда не парсится. Если событие ещё активно, оно отклоняется целиком: предыдущие законченные строки не выдаются за полное текущее дерево. Это консервативное правило действует и когда незавершённый хвост начинается с `[`. Уже закрытые события сохраняются отдельно.

## Ограничения и отказы

Все keyword limits — положительные целые числа; bool не принимается.

| Параметр | Значение по умолчанию | Действие |
| --- | --- | --- |
| `max_source_bytes` | 1 GiB | Отказ всему вызову до чтения слишком большого снимка |
| `max_lines` | 20 000 000 | Отказ всему вызову при превышении числа физических строк |
| `max_events` | 512 | Отказ всему вызову при следующем распознанном заголовке; отклонённые события тоже учитываются |
| `max_line_bytes` | 512 | Посторонняя строка пропускается ограниченным буфером; активное событие отклоняется |
| `max_event_lines` | 20 000 | Отклоняется событие; заголовок входит в число строк |
| `max_event_bytes` | 16 MiB | Отклоняется событие; заголовок и исходные LF/CRLF входят в размер |
| `max_retained_bytes` | 32 MiB | Отказ всему вызову, если сумма исходных байтов успешно разобранных событий превысит бюджет |
| `chunk_bytes` | 64 KiB | Максимальный размер одного чтения |

Парсер дополнительно ограничивает глубину и число узлов собственными опубликованными defaults. Буфер физической строки сохраняет не более `max_line_bytes+1` байтов, независимо от её реальной длины. Превышение лимита события сразу очищает сохранённые строки; сканирование, счётчики и SHA продолжаются до следующей границы. Другая часть отклонённого события не выдаётся за самостоятельное дерево.

Общий retained budget проверяется после успешной проверки грамматики, до добавления дерева в `events`; отклонённые события и посторонние строки его не расходуют. Равенство бюджету разрешено. Во время проверки возможно одно дополнительное дерево-кандидат, уже ограниченное per-event лимитами. Бюджет измеряет исходные байты событий, а не точное число байтов Python heap. При превышении возвращается `retained_limit` с первой физической строкой события-кандидата, без частичного документа.

`rejected` содержит только `{start_line,end_line,boundary,header_trailing_space,code,line}`. Bool framing сохраняется и для отклонённого события. Первая причина отказа события сохраняется: `event_line_limit`, `event_lines_limit`, `event_bytes_limit`, `incomplete_final_line` или `grammar_<код парсера>`. `line` — физическая строка ошибки. Здесь нет исходного текста.

Ошибки всего снимка — `BuildLogError(ValueError)` с фиксированными `code`/`line`: `limits`, `path`, `read`, `source_limit`, `line_limit`, `event_limit`, `retained_limit`, `source_shrank`. Номер 0 обозначает отказ до чтения строки. Частичный документ при таком исключении не возвращается. Сообщения состоят из одной строки без текста источника и завершающей точки.

`source.path` и содержимое `events[].tree` могут содержать частные данные. Результат принадлежит локальному вызывающему коду; его нельзя публиковать как безопасную публичную projection. Этот адаптер ничего не записывает и не выбирает последнее событие как текущий билд.

## Явное окно для большого журнала

`import-log --tail-bytes N` использует отдельный `damage_lab.logwindow.collect(path, budget=N)` перед строгим reader. `N` — положительное целое до 2 МиБ. Режим по умолчанию не меняется и по-прежнему отказывает при превышении прежнего `source_limit`.

Сборщик открывает обычный файл, фиксирует его размер, читает только конечный диапазон блоками до 64 КиБ и не следует за дописыванием. Короткое чтение отклоняется без повторов. Если начало диапазона ненулевое, байты до первого LF консервативно отбрасываются; это может потерять и целую начальную строку. Последняя незавершённая строка сохраняется для прежнего отказа parser, а не удаляется ради принятия неполного события.

CLI разбирает временную копию тех же байтов, включая `--context`, и удаляет её при штатном завершении. Неотфильтрованные исходные байты окна не копируются в отчёт. Сохраняются проекции, хеш и диапазон; контекст остаётся ограниченным и фильтрованным по прежнему контракту.

Только этот режим использует `tli-log-import-v1` версии `0.4.0`; обычный режим сохраняет `0.3.2`. В `source` записаны `kind=retained_log_window`, `sha256_scope=retained_window`, `line_scope=retained_window`, `bytes_retained=false`. `source.path` именует исходный файл, но `source.sha256` относится исключительно к разобранному окну. `source.bytes_read` — размер разобранных байтов; `window.bytes_read` дополнительно включает отброшенное начало.

Объект `window` формата `tli-log-window-v1` хранит `origin_path`, `opened_bytes`, `read_start`, `read_end`, `bytes_read`, `discarded_leading_bytes`, `payload_start`, `payload_bytes`, `payload_sha256` и `original_sha256=null`. Глобальное смещение строк не вычисляется. После ротации или изменения исходника воспроизведение прежнего окна может стать недоступным; сохранённый хеш не восстанавливает отсутствующие байты.

`atomic=false` и `currentness=unknown` не повышаются даже при неизменных размерах файла. События остаются раздельными, выбранный персонаж и навык неизвестны, полный импорт и готовность DPS не подтверждаются.
