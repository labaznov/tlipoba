# Автоматический импорт: текущий срез

Цель — получить весь билд по коду/ID или из игры без скриншотов и переписывания характеристик. Публичный игровой API пока не подтверждён; см. [исследование](research/build-import-api.md). Код игры декодируется в 16 байт, но не содержит доказанного полного графа билда.

Сейчас внешний локальный экспортёр сохраняет пакет вместе с `native-stats.json`: числовые данные извлекаются из сохранённого `rpc.ViewPlayerAttrInfo`. Манифест связывает этот файл с пакетом, а tlipoba подхватывает его автоматически при статусе `decoded`. Чтение файлов не требует запущенной игры и не мешает игроку. Код экспортёра пока находится вне публичного проекта.

Для старого пакета отдельный файл можно создать утилитой разработчика:

```powershell
python ПУТЬ_К_ЭКСПОРТЁРУ/native_stats.py ПАКЕТ/source.json local-data/native-stats.json
```

В таком случае к команде добавляется `--native-stats local-data/native-stats.json`; явный путь имеет приоритет над файлом из манифеста.

## Импорт без ручных показателей

```powershell
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --output local-reports/import
```

Команда не принимает обязательных скриншотов или наблюдений: она читает доступные данные пакета, проверяет хеши и сохраняет состав билда, автоматические статы и конкретные пробелы покрытия. Выход — новый каталог с `import.json`, `database.sqlite` и автономным HTML. Отсутствующие показатели и замер на манекене не заменяются нулями. Результат пока имеет статус частичного импорта.

`--observations` остаётся необязательным инструментом разработчика. Когда автоматические источники содержат все необходимые параметры, расчёт запускается без этого файла. Условия боя выбираются отдельно; наличие статов не доказывает полный боевой DPS.

## Точные параметры из обычного журнала игры

Клиент пишет пары `RoleAttrMgr@Attri.Id` и `RoleAttrMgr@[1]` при открытии панели характеристик. Сборщик входит в публичный проект:

```powershell
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --game-log "ПУТЬ_К_ИГРЕ/UE_game/TorchLight/Saved/Logs/UE_game.log" --output local-reports/import
```

`--game-log` читает исходный журнал напрямую. Не нужны промежуточный JSON, скриншоты или переписывание статов. В SQLite остаётся только отфильтрованный документ панели; полный журнал не сохраняется. Источник и строки доказательств получают хеш и число байтов именно прочитанного снимка, без повторного хеширования растущего файла. Поле `panel_log.input_kind` различает `game_log` и `panel_log`.

Если требуется отдельный переносимый снимок:

```powershell
python -m damage_lab.panellog "ПУТЬ_К_ИГРЕ/UE_game/TorchLight/Saved/Logs/UE_game.log" local-data/panel-log.json
python -m damage_lab import --package "ПАПКА_ЭКСПОРТА" --panel-log local-data/panel-log.json --output local-reports/import
```

`--game-log` и `--panel-log` взаимоисключающие; оба варианта доступны также для условного расчёта.

Игроку не требуется переписывать значения. Журнал читается только до размера на момент открытия файла, дописанные во время игры строки остаются за границей снимка. Незаконченная последняя строка не превращается в число. Посторонние игровые сообщения не входят в выходной JSON. Старый выходной файл не перезаписывается.

`tli-panel-log-v1` сохраняет исходные числовые токены, ID и имя характеристики, номера строк, время и кадр. Импортёр принимает только согласованный полный набор, сопоставленный с целочисленным Spell DPS из серверного снимка пакета в пределах ±0,5. Повторы одинакового состояния разрешены; разные подходящие состояния дают ошибку неоднозначности. Дробное значение Spell DPS из журнала уточняет округлённое серверное значение с сохранением обоих источников.

Если после выбранного совпадающего состояния есть более новые панели с другим Spell DPS, отчёт предупреждает об историческом выборе. Он не объявляет их другим персонажем и не переносит новые показатели в старый экспорт. Возврат к совпадающему состоянию снимает именно это предупреждение; личность персонажа по-прежнему не подтверждается.

Это сопоставление состояния, а не доказательство личности: `identity_verified` остаётся `false`. Время из журнала может относиться к ранее открытой панели. Код билда и точный набор экипировки журнал не подтверждает; универсальный импорт по коду остаётся отдельной задачей.

Подтверждённые ID журнала:

| ID | Характеристика | Нормализация |
| --- | --- | --- |
| 10103 | Spell DPS | Число без округления |
| 11800 | Total Spell Damage | Минимум и максимум |
| 21000 | Spells cast per second | Касты в секунду |
| 21212 | Spell Critical Strike Chance | Проценты / 100; два значения допустимы только при равенстве |
| 21400 | Spell Critical Strike Damage | Проценты / 100 |
| 21714 | Max Tangle Quantity | Целое число |
| 21715 | Additional Tangle Attach Quantity | Целое число |
| 11000 | Cold Penetration | Проценты / 100 |
| 11201 | Armor DMG Mitigation Penetration | Необязательный показатель; проценты / 100 |

Неподдержанные ID сохраняются в исходном документе. Таблица не устанавливает соответствие с числовыми ID внутри protobuf `attrInfo`: это разные пространства идентификаторов.

Для условного расчёта к обычной команде можно добавить `--panel-log`, опустив `--observations`. При нехватке любого обязательного параметра расчёт завершается с перечнем пробелов, а не подставляет нули.

Пробивание брони не добавлено в обязательные девять полей: старые источники остаются пригодными для прежней модели. При выборе нового сценария брони значение можно взять через `armor_penetration: "panel"`; если поле не извлечено, расчёт завершается ошибкой. Порядок пробивания и эффективность брони цели задаются отдельно, см. [боевой контекст](COMBAT.md).

## Параметры навыков по уровню

Новые пакеты содержат `levelValues`: значение из строки точного уровня, исходную ячейку таблицы и происхождение. tlipoba сохраняет эту проекцию в `skill_values` и SQLite. Числовые ячейки и рациональные дроби проверяются; несогласованный уровень или значение отклоняется. Неразрешённые уровни не получают вымышленных чисел, а старые пакеты явно помечаются `unavailable`.

Статус `resolved` означает разрешение строки каталога, а не независимое подтверждение формулы для текущей версии игры. В частности, описания поддержки могут показывать первый уровень, а кэш навыка — старую версию. Эти параметры не применяются повторно к готовым агрегатам панели; [ограничения таблиц](research/support-level-values.md) сохраняются.

`level` здесь — уровень навыка в экспорте. Итоговый эффективный уровень с прибавками от вещей и талантов пока отдельно не восстановлен; строка базового уровня не подменяет отсутствующую строку эффективного уровня.

## Контракт входа

`build-resolution.json` из новых пакетов также импортируется автоматически. `manifest.buildResolution` связывает его с точными байтами source; проверяются статус оценки, тип признака переданного кода и `identityVerified: false` / `transportVerified: false`. Без переданного кода оценка может быть `unbound`, при совпадении — `matched_saved_code`. Это сравнение с сохранённым полем контроллера, а не подтверждение личности пэйлоада, свежести, навыка панели или работающего API. Свежесть остаётся `unknown`. Оценка сохраняется в JSON, SQLite и обоих HTML; ошибки и отсутствие артефакта у старого пакета остаются явными пробелами. Нового ручного параметра CLI для чтения артефакта не требуется.

Новые пакеты содержат `import-coverage.json` и `manifest.importCoverage`. Они автоматически подхватываются той же командой импорта. Проверяются точное имя, хеш артефакта и точные хеши прочитанных source/guide, статус `diagnostic` с девятью областями либо `error` с нулём областей, а также `importComplete: false`. Если аудит не читал guide, это отдельный явный случай с `guideSha256: null`; наличие файла guide в пакете само по себе не меняет его происхождение.

`import_coverage` в JSON, SQLite и обоих HTML различает полученный состав и интерпретацию боевых эффектов. Области: предметы, навыки, геройские свойства, таланты, плиты, пакты, native-статы, идентичность навыка панели и активация поддержек. `observed` означает наличие записей, а не подтверждённое действие бонусов. Пара хешей удостоверяет прочитанные файлы; связь guide с исходным снимком остаётся `unverified`. Аудит не меняет DPS. Ошибка аудита и старый пакет без него дают явный пробел; ложные заявления о полноте и несовпадающие хеши отклоняются. Ручного файла покрытия от игрока не требуется.

Новые пакеты дополнительно содержат `trait-ranks.json` и дескриптор `manifest.traitRanks`. Импорт подхватывает его автоматически, проверяет точное имя файла, SHA256 артефакта, SHA256 исходного `source.json`, число свойств и `rankRuleVerified: false`. В SQLite, JSON импорта и расчёта, а также в обоих HTML-отчётах сохраняется безопасная проекция `trait_ranks`; исходные instance ID и посторонние native-поля в неё не попадают.

Для связанных воспоминаний показаны два именованных кандидата: `client_fixed = C` и `fixed_plus_enhance = C + E`. Их арифметика и пути проверяются; `C = S + F` служит проверкой согласованности, поэтому fixed affix не прибавляется к `C` повторно. Совпадение кандидатов не выбирает правило. Итоговый `rank` остаётся `null`, базовое свойство без проверенного источника не получает ранг 1, а отсутствие `E` не становится нулём. Эти кандидаты не изменяют DPS.

Старый пакет без этого артефакта остаётся пригодным для частичного импорта с явным пробелом. Проверенный артефакт ошибки тоже сохраняет частичный импорт без кандидатов; несовпавшие хеши, путь вне фиксированного имени и ложное заявление о проверенном правиле отклоняются. Чтобы получить новые данные, пакет можно заново сформировать из сохранённого источника; переписывать ранги игроку не требуется. Источники и неподтверждённая семантика `C` и `E`: [исследование Hero Memories](research/hero-memory-ranks.md).

Нормализованный формат `tli-native-stats-v1`, статус `decoded`. `source.sha256` обязан совпасть с точным `source.json` того же пакета. Для известных полей сохраняются `sourcePath`, номер wire, тип, доказательство и факт, что универсальная схема протокола ещё не подтверждена.

| Поле | Wire | Назначение | Доказательство |
| --- | --- | --- | --- |
| `spell_dps` | `1.10`, varint | Панельный Spell DPS | Одно независимое сопоставление; `evidence: corroborated`, `protocolVerified: false` |
| `survival` | `1.11`, varint | Survival, отдельный показатель | То же ограничение; не множитель урона |

Автоматические значения заменяют соответствующие прежние наблюдения с явной записью конфликта и происхождения. Исходный файл наблюдений сохраняется отдельно. SQLite содержит документ автоматических статов и хеш его файла; JSON расчёта — сводку покрытия. При несовпадении хеша, неподдержанной схеме или неправильных известных полях импорт завершается ошибкой.

## Что ещё требуется

Числовые stat ID серверного protobuf пока не имеют проверенной таблицы имён. Журнал уже даёт девять обязательных параметров текущей модели, но не события попаданий, стеки Heat, дебаффы или боевой DPS. Текущий снимок содержит ID выбранных свойств героя, но не их уровни. Эффекты protobuf-плит расшифрованы, их размещение ещё неизвестно. Наличие слотов, вещей и описаний не означает полного расчёта всех их эффектов.

Исследование полей воспоминаний сужает варианты ранга, но не подтверждает сложение внутренних полей. Достижение порога уровня само по себе не доказывает выполненный апгрейд свойства; [источники и кандидаты](research/hero-memory-ranks.md) сохраняют этот пробел. Выбор ранга по совпадению DPS запрещён.

Нужны подтверждение привязки состояния к билду, уровни свойств героя и проверка боевых механик. Новый доступ к памяти проводится отдельно от чтения журналов, после предупреждения игрока.

## Наблюдаемая установка навыков

Новый пакет с `manifest.installedSkills` подхватывается обычными командами автоматически. [Source-bound inventory](SKILL_BUNDLE.md) проверяет точные байты artifact и исходного снимка и сохраняет безопасные aliases, публичные skill ID, gem levels, координаты и co-membership. JSON, SQLite и HTML различают установку, неизвестную активацию и неизвестный effective level. Роль поддержки не выводится из соседства слотов, готовый DPS не корректируется. Ошибка producer либо отсутствие descriptor остаются пробелом получения данных; отсутствие наблюдаемого слоя не становится нулевым составом.

## Эффекты установленных специальных поддержек

`manifest.installedSupportEffects` автоматически подключает фиксированный
`installed-support-effects.json` версии `0.2.0`. Проверяются SHA прочитанных bytes,
source hash, версии, typed counts и четыре literal false claims. Безопасные
`installed_support_effects` и `installed_support_catalog` сохраняются парой в
SQLite, `import.json`, `calculation.json` и обоих HTML. Каталог описывает declared
локальные master/English slices; его hashes не выдаются за повторную проверку
cache или текущего клиента. [Контракт reader](SUPPORT_BUNDLE.md) описывает границы.

Роллы из собственного native Prefix отделены от литералов каталога. Typed
candidate требует master и English своей категории; withheld ID не разрешается
как кандидат. Неизвестные layers и значения сохраняют `null`, а error producer
даёт явный coverage gap без пустого inventory. Повреждённые bytes или ложные
claims отклоняются до создания базы. У старого пакета descriptor может отсутствовать.
Активация, effective level, patch и grouping остаются неизвестными; наличие
кандидата не меняет ранее рассчитанный DPS и не подтверждает полноту импорта.
