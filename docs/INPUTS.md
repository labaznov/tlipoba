# Входные данные первого MVP

Текущий вход — адаптер пакета существующего экспортёра и вручную записанных показателей панели. Это рабочий контракт для первого билда Carino, а не окончательная универсальная схема всех систем Torchlight Infinite. Реализация находится в `damage_lab/archive.py` и `damage_lab/engine.py`.

## Пакет экспортёра

Архиватор принимает каталог с пятью файлами, отдельные JSON наблюдений и фактов, а также путь к **новой** SQLite-базе. Существующая база не перезаписывается.

| Файл | Что использует адаптер |
| --- | --- |
| `build.json` | `loadouts.currentLoadoutId` и `loadouts.loadouts`; текущий loadout должен находиться ровно один раз |
| `guide-data.json` | `character`, `gear`, `skillGroups`, `talentTrees`, `heroMemories`; имена и описания для инвентаря |
| `manifest.json` | `buildSha256`, `capturedAt`, необязательные `identity.title`, `status`, `synthetic` |
| `transfer-report.json` | `complete`, `canClaimFullTransfer`, `issues`, `systems`; ограничения переноса |
| `source.json` | Только SHA-256 и размер исходных байтов; содержимое не переносится в базу |

`manifest.buildSha256` должен точно совпадать с SHA-256 **байтов** `build.json`, включая форматирование и перевод строки. Хеши остальных файлов фиксируются для происхождения данных; они не проверяются по манифесту. Совпадение хеша не доказывает полноту или правильность экспорта.

Текущий loadout содержит `skills.activeSkills`, `skills.passiveSkills` и `skillTree.slots`. При непустых слотах талантов адаптер сверяет `treeId`, ранги `nodePoints` с выбранными узлами `rank > 0` и наличие выбранных core в guide. Для замены core призмой используется `prismCoreTalentOverride`; отсутствие описания отмечается в покрытии.

Guide содержит массивы вещей с `name` и `affixes[].text`, групп навыков с `kind`, `main`, `supports`, деревьев с узлами и геройских воспоминаний с текстами эффектов. Пустые массивы допустимы в синтетическом примере. Этот описательный инвентарь ещё не означает, что каждый эффект участвует в вычислении.

База сохраняет JSON build, manifest, transfer, observations и facts, таблицы инвентаря и происхождения. Полный guide и его `sourceSections` не сохраняются. База может содержать пути, идентификаторы и данные персонажа из остальных документов: реальную базу и отчёты нужно оставлять локальными.

## Наблюдения

Документ имеет поля `synthetic`, `evidence`, `panel`, `benchmark`, необязательные `notes`. `synthetic: true` явно обозначает вымышленные данные; архиватор также распознаёт эту метку в guide или manifest. Она не является проверкой подлинности реального экспорта.

`evidence` — словарь именованных источников, каждый с `path`. Строки панели ссылаются на ключ этого словаря. Для реального существующего файла фиксируются SHA-256, размер и время изменения. Недоступный скриншот даёт предупреждение; его отсутствие не удаляет записанное значение. Время изменения файла не считается временем боя.

Одна строка `panel`:

```json
{
  "key": "crit_chance",
  "label": "Spell Critical Strike Chance",
  "value": 0.4137,
  "display": "41.37%",
  "unit": "fraction",
  "evidence": "fixture"
}
```

Обязательные показатели панели:

| `key` | Ожидаемая `unit` | Значение |
| --- | --- | --- |
| `spell_dps` | `damage/s` | Панельный Spell DPS |
| `hit_min`, `hit_max` | `damage` | Нижняя и верхняя границы показанного урона |
| `cast_rate` | `casts/s` | Кастов в секунду |
| `crit_chance` | `fraction` | Доля, например `0.4137` для 41.37% |
| `crit_multiplier` | `multiplier` | Полный множитель, например `2.87` для 287% |
| `max_tangles` | `count` | Максимум созданных Tangle; ядро поддерживает 0–4 |
| `extra_attachments` | `count` | Дополнительные прикрепления сверх базового одного |
| `cold_penetration` | `fraction` | Доля пробивания, например `0.07` для 7% |

Другие строки могут сохраняться как наблюдения, но ядро не начинает использовать их автоматически. Дубли ключей, нечисловые и бесконечные значения, неизвестные единицы и ссылки на отсутствующий ключ evidence отклоняются. Архиватор проверяет соответствие `display` и `value`, а для обязательных показателей и бенчмарка — также единицу конкретного ключа. Семантика дополнительных показателей остаётся обязанностью поставщика входа.

`benchmark` содержит `label`, один ключ `evidence` для всех строк и массив `values` с такими же `key`, `label`, `value`, `display`, `unit`. Обязательны `average_dps`, `duration`, `highest_5s`, `average_5s`, `survival`; единицы соответственно `damage/s`, `s`, `damage/s`, `damage/s`, `survival`. Эти данные сохраняются отдельно от панели, с префиксом `benchmark_` в таблице наблюдений. Подпись окна бенчмарка не определяет уровень персонажа.

## Единицы и точность

Проценты преобразуются в доли при записи `value`: 13% → `0.13`, 667% полного критического урона → `6.67`. Дополнительные 26% урона означают параметр `0.26`, а не готовый множитель `1.26`. Количества и числа попаданий — целые числа.

`display` сохраняет видимую запись. Разрешены десятичная точка, запятые как разделители тысяч, суффиксы `K`, `M`, `B`; для `casts/s` ожидается `/s`, для процентов — `%`, для секунд — `s` или `HH:MM:SS`. Например, `730.4K` соответствует `730400`, `1.1M` — `1100000`.

Поле precision фиксирует половину последнего отображённого шага: для `1.1M` это ±50000. Это характеристика записи, не доказанная погрешность игры. Ядро считает по записанным центральным значениям и пока не распространяет интервалы точности через формулу. Недостающие цифры не восстанавливаются.

## Локальные факты

Файл `damage_lab/data/tlidb-ss14.json` содержит `patch`, `checkedAt`, `sources` со ссылками, сведения `chromatic`, `rules` и список `limits`. Ограничения включают неподтверждённую таблицу уровней выше 20, конфликт старого каталога и неустановленную трактовку shotgun coefficient.

Архиватор сохраняет документ и его SHA-256 без полной проверки схемы. Наличие факта не подключает его автоматически к математике: например, retention задаётся сценарием. При расширении ядра нужно явно связать используемый факт, формулу и тест.

## Условия боя

`engine.calculate(panel, condition)` требует явный словарь условий:

| Поле | Смысл |
| --- | --- |
| `basis` | `panel` использует готовый `spell_dps`; `hit` вычисляет средний hit × cast rate × ожидание крита |
| `active` | Число активных Tangle, не выше `max_tangles` |
| `hits` | Число попаданий одного Tangle в цель; не автоматически число снарядов |
| `retention` | Оставшаяся доля урона каждого следующего попадания, от 0 до 1 |
| `lucky` | Булево значение; в режиме `hit` даёт вероятность `1 − (1 − p)²` |
| `critical_more` | Дополнительный урон только критов, доля; используется в режиме `hit` |
| `resistance` | Сопротивление холоду цели как доля |
| `taken` | Внешний увеличенный получаемый урон как доля, ещё не включённый в исходную панель |
| `uptime` | Доля времени нанесения урона, от 0 до 1 |

Прикреплённые Tangle: `min(max_tangles, 1 + extra_attachments, active)`. Shotgun-сценарий: `1 + (hits − 1) × retention`, а при нуле попаданий — ноль. Множитель сопротивления: `max(0, 1 − resistance + cold_penetration)`. В режиме `hit` cast rate ограничивается 30.

Результат всегда условный: трактовка панели как одного снаряда одного Tangle не подтверждена. Броня предполагается нулевой; Heat Up, Burning Red, проклятие и другие состояния не восстанавливаются из снимка автоматически. В режиме `panel` предметные множители, крит и скорость повторно не добавляются. Бенчмарк не определяет множители формулы.

## Публичный пример

`examples/make_fixture.py` создаёт новый каталог через функцию `fixture(output)` с вымышленным пакетом, наблюдениями и независимым вымышленным бенчмарком. Он не читает реальные захваты и не содержит данных аккаунта. Пример проверяет путь импорта и арифметику; он не доказывает воспроизведение игрового DPS.
