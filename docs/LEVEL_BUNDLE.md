# Приём кандидатов уровней навыков

`levelbundle.read(package, descriptor, source_sha256, installation)` принимает только
`installed-level-candidates.json` producer `0.1.2` с resolver `0.3.1`. Ограниченный
UTF-8 JSON проверяется по SHA-256 descriptor; source hash должен совпасть с хешем,
который передал импортёр после чтения `source.json`. Сам reader повторно не читает
source, cache или auxiliary. Возвращаемый origin фиксирует реальный путь, SHA-256,
число прочитанных байтов и наличие сохранённого диагностического документа.

`summary(bundle, installation)` повторно проверяет canonical DTO и возвращает
отделённую проекцию без неизвестных свойств. Все четыре признака готовности и
проверенности остаются `false`. Отсутствие состава отличается от полученного
пустого состава: первое сохраняет `null`, второе — пустые коллекции и нулевые
счётчики. Ошибка producer даёт `None` и origin со `stored=0`; только ошибки
`source_missing` и `source_unreadable` допускают неизвестный source hash.

Список запрошенных ID должен точно покрывать различные положительные ID из
проверенного installed inventory. Для единственной установки совпадают путь и
наблюдаемый уровень камня. Повторные установки сохраняют неоднозначность с
неизвестным уровнем; первый экземпляр не выбирается. Счётчики сверяются с
проверенными targets, candidates, gaps, catalog members и auxiliary.

Catalog provenance допускает только фиксированные домены SS14 и ограниченные
координаты точных byte slices. Повторные members, пересекающиеся диапазоны одного
wrapper и разные SHA одного wrapper отклоняются. Эти метаданные остаются
заявлениями producer: они не подтверждают сеть или текущую версию игры.
Auxiliary допускают только два фиксированных логических имени с SHA и размером;
переданный bridge не становится проверенной игровой идентичностью. Кандидат с
bridge требует supplied auxiliary; каждая привязка кандидата и цели требует
соответствующего master в provenance. Счётчики census каталогов сверяются с
заявленным набором members, а число наблюдаемых камней — с installed inventory.

Каждый target проходит `levelcandidates.project/summary`. Сохраняются точные
строковые amounts, собственные роллы, вычисленные привязки талантов, литералы
каталога, неопределённость рангов и покрытие тринадцати областей. Ни суммы
прибавок, ни effective level, ни DPS reader не вычисляет.

Пакет с `manifest.installedLevelCandidates` переносит canonical документ в
SQLite, import/calculation JSON и вложенный record команды `inputs`. Три HTML
отчёта показывают весь проверенный набор целей, включая неоднозначные установки
и цели вне выбранного alias. Ошибка producer сохраняет origin и coverage gap
без semantic документа; legacy пакет остаётся доступным с явным пробелом.
Проверки выполняются до создания SQLite. Статы, benchmark и прежний условный
расчёт не меняются.
