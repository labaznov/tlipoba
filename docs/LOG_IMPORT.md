# Диагностика состава из обычного журнала

Команда читает локальный журнал и сохраняет отдельные проекции подходящих событий без скриншотов, управления игрой и ручного ввода показателей:

```powershell
python -m damage_lab import-log --game-log "ПУТЬ_К_ЖУРНАЛУ/UE_game.log" --output local-reports/log-import
```

Результат — `log-import.json` и самостоятельный `index.html` в новом каталоге. Существующий каталог не перезаписывается. Ошибка чтения, структуры, выбранного события или записи завершает команду с кодом 1; частичный каталог результата не публикуется. Сообщение ошибки не копирует содержимое исходного журнала.

По умолчанию команда сохраняет **все подходящие события отдельно**. Это кандидаты по наблюдаемой структуре, а не проверенные ответы на код билда. Последнее событие не выбирается автоматически, значения разных событий не объединяются. Отсутствие подходящего события означает только отсутствие поддержанной структуры в прочитанном снимке.

При разработке можно явно выбрать один zero-based индекс из `selection.candidates`:

```powershell
python -m damage_lab import-log --game-log "ПУТЬ_К_ЖУРНАЛУ/UE_game.log" --event 2 --output local-reports/log-event
```

Выбор индекса не подтверждает личность персонажа, свежесть, текущий выбранный навык или связь с прежним Pro Build. Журнал может печатать собственное состояние игрока и другие таблицы; имя файла и время заголовка не решают эту связь. Runtime и код остаются unknown, `import_complete=false`.

Reader хеширует фиксированный начальный снимок файла с ограничениями размера, числа строк, событий и сохранённых байтов. JSON результата содержит хеш и размер снимка, счётчики принятия и отдельные безопасные domain projections. Исходные деревья, произвольные rejected payloads и неразрешённые поля account/instance не копируются. Детали reader описаны в [BUILD_LOG](BUILD_LOG.md), точные пути и allowlist — в [LOG_BUILD](LOG_BUILD.md).

HTML показывает покрытие каждого домена и лексические значения с координатами источника. Статус complete относится к напечатанному поддереву. Elided и not_printed не становятся нулём, пустым списком или подтверждением отсутствия предметов. Числовой вид токена не подтверждает исходный числовой тип и точность игрового printer.

Это доступный слой приобретения состава. Он ещё не восстанавливает `ServerSource`, не переносит неподтверждённые условия в unconditional effects и не вычисляет DPS. Для полноценного автоматического импорта остаются привязка события к персонажу/коду, заполнение обрезанных навыков и талантов и проверенные карты типов и каталогов.
