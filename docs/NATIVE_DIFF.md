# Диагностика двух снимков без переноса частных показателей

Команда `native-diff` проверяет отчёт внешнего `native_wire_diff` и два исходных
файла, затем сохраняет сводку JSON и пассивный HTML в новый каталог:

```powershell
python -m damage_lab native-diff --artifact local-data/diff.json --source-a local-data/a/source.json --source-b local-data/b/source.json --output local-reports/native-diff
```

Это отдельная диагностическая команда. Она не меняет импорт персонажа,
наблюдения панели, SQLite расчёта или входы DPS. Подготовка отчёта внешним
экспортёром остаётся отдельным шагом; автоматического сбора пары состояний
эта команда не выполняет. Скриншоты и переписывание значений не нужны.

Consumer принимает только формат `tli-native-wire-diff-v0/0.1.0` с объявленным
decoder `tli-native-stats-v1/0.2.0` и статусом `compared` либо `identical_sources`.
Проверяются закрытая схема, допустимые виды строк, их уникальность и порядок,
число строк и счётчики статусов. В обоих исходных файлах проверяются фактические
байты, размер и SHA256 относительно отчёта. Исходники не декодируются повторно.
Producer-отказы и неподдержанные версии отклоняются явно.

Ограничения: отчёт до 1 MiB, каждый исходник до 16 MiB, до 8192 строк отчёта.
Размеры проверяются до хеширования, глубина до 64 и число лексических элементов
JSON до 100000 — до разбора. Лимит элементов может отклонить большой допустимый
отчёт раньше лимита строк. Дубли ключей, нечисловые константы и некорректные числовые строки
отклоняются. Это выбранные пределы consumer, без обещания принять любой отчёт
экспортёра. Существующий каталог результата не перезаписывается; JSON и HTML
публикуются вместе после проверки входов.

Ошибки проверки показывают только фиксированный код причины, без входных
путей и содержимого файлов; остальные ошибки ввода или записи имеют общий текст.

В сводку переносятся только хеши, размеры и агрегированные счётчики. Численные
показатели, wire paths, statIds, автор, исходный отчёт и содержимое снимков туда
не копируются. Реальные входы и результаты должны оставаться в ignored каталогах.

`sources=bytes_match` означает совпадение двух ссылок с переданными байтами.
`comparisons=producer_reported` означает, что сравнения заявил producer:
consumer не пересчитывает delta, ratio или сокращение дробей и не доказывает
выполнение decoder. Совпадение хешей не подтверждает текущего персонажа,
выбранную страницу, атомарность или причинность изменения. Все эти признаки
остаются неизвестными, `arithmeticReady=false`. Точный DPS Carino не изменяется.
