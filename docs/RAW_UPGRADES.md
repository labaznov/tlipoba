# Сравнение полных исходных spell-сценариев

`damage_lab.rawupgrades.evaluate(document)` сравнивает полные входы [rawspell](RAW_DAMAGE.md), включая изменения flat damage, increased, базы и effective level. Это чистая библиотека без сети, рынка, записи файлов или доступа к игре. Результат — ожидание **одного источника до защиты цели**, а не полный боевой DPS Carino.

В отличие от [сравнения target/reference](UPGRADES.md), каждый кандидат полностью пересчитывается через `rawspell.evaluate`. Старые и новые предметные вклады не складываются автоматически. Нет панельного агрегата, произвольного коэффициента прироста или подгонки к замеру.

## Вход

`tli-raw-upgrade-scenario-v1` требует ровно четыре поля:

| Поле | Контракт |
| --- | --- |
| `format` | `tli-raw-upgrade-scenario-v1` |
| `baseline` | Полный `tli-raw-cold-spell-v1`, включая source gates, missing и notes |
| `currency` | Непустая общая валюта вызывающего кода |
| `candidates` | Массив полных замен |

Кандидат содержит ровно `id`, `name`, `scenario`, `cost`, `missing`. `scenario` — полный новый rawspell-сценарий; `cost` — конечное неотрицательное число либо `null`, если цена неизвестна. `missing` — явный список неподдержанных эффектов. Он добавляется к `scenario.missing` в независимой копии до вычисления, поэтому неполный кандидат получает blocked raw-result, а не частичную числовую дельту.

Идентификаторы кандидатов уникальны. Текстовые поля требуют непустую строку без пробелов по краям, максимум 1024 символа; списки — максимум 1000 элементов. Числовые bool, отрицательные цены, NaN/Infinity, неподдержанные поля и malformed вложенные сценарии отклоняются. Проверки rawspell выполняются для baseline и каждого кандидата, даже если baseline уже blocked.

У всех вариантов обязаны совпадать `context.skill_id`, `context.catalog_sha256`, `damage.roll_model` и `casting.frequency`. Источник, effective level, база и прочие поддержанные параметры могут изменяться: каждый сценарий должен иметь собственные подтверждённые gates. Изменение числа не подтверждает gate автоматически; ссылки evidence остаются утверждениями вызывающего адаптера. Версия, полнота и активация эффектов требуют реального нормализатора.

Явные неизвестные группы поддерживаются по контракту rawspell. Общие
`damage: null` или `casting: null` допустимы только с обеих сторон: сравнение
сохраняет blocked и не назначает roll/tick policy. Неизвестная группа только
с одной стороны вызывает контролируемый `ValueError`, поскольку общая policy
не установлена. Неизвестный `critical` также блокирует дельту и рейтинг;
известные skill/catalog checks продолжают действовать.

## Результат и блокировки

Отчёт `tli-raw-upgrade-report-v1` сохраняет detached `scenario`, исходный raw-result в `baseline`, raw-result каждого кандидата, `currency`, `price_source: caller` и `quantity_scope: pre_defence_single_caster`. Общий `status` равен статусу baseline: blocked либо conditional; условный отчёт может содержать заблокированные варианты. Общие `gaps` относятся к baseline, у каждого кандидата отдельно сохраняется объединение baseline/candidate gaps.

Для полного сравнения возвращаются `pre_defence_dps`, `delta = candidate − baseline`, `relative = delta/baseline` и `per_cost = delta/cost`. Если baseline blocked, все дельты и отношения равны `null`, рейтинг пуст. Если кандидат blocked либо имеет missing, его дельта и отношения также `null`: числовая часть неполной модели не вычитается. При этом самостоятельный raw-result другого полного сценария сохраняет своё значение.

При нулевом baseline `relative` равен `null`; при нулевой или неизвестной цене `per_cost` равен `null`. Остальные дельты и отношения должны быть конечными. Исчезновение ненулевого отношения до нуля вызывает ошибку. Библиотека не округляет результат для совпадения с панелью или для создания равного рейтинга.

| Статус кандидата | Значение |
| --- | --- |
| `blocked` | Неполон baseline или кандидат; числового сравнения нет |
| `not_upgrade` | Полная модель дала неположительную дельту |
| `unpriced` | Положительная дельта, цена неизвестна |
| `free` | Положительная дельта при явно заданной нулевой цене |
| `upgrade` | Положительная дельта при известной положительной цене |

`eligible_for_ranking` отмечает полный положительный прирост независимо от цены. `eligible_for_cost_ranking` дополнительно требует известную цену. `ranking` включает только вторую группу: бесплатные изменения идут отдельным первым классом без Infinity, затем платные по убыванию delta/cost. Равенство разрешается меньшей ценой, затем ID; бесплатные упорядочены по ID. Неизвестная цена не становится нулевой.

## Синтетический контроль

Baseline: Physical base `[101,149]`, flat Physical `[7,11]`, flat Cold `[13,19]`, effectiveness `2`, increased all/Physical/Cold `.2/.3/.5`, без additional damage. При chance `.2`, полном crit `3`, critical-only more `0` и двух кастах в секунду pre-defence DPS равен `953.12`. Полная замена flat Physical на `[17,23]` даёт `1076.32`, delta `123.2`; старые `[7,11]` не остаются в сумме. Отдельное увеличение Physical increased меняет только converted ветвь, а native Cold сохраняет свой путь.

Проверка: `C:/Python313/python.exe -m unittest discover -s tests -p test_rawupgrades.py -v`.

Готового импорта модификаторов настоящих предметов, рынка, защиты цели, Tangle/projectile topology и боевого uptime в этом модуле нет. Рейтинг относится только к общему rawspell-контексту с явными ценами. Он не является рекомендацией купить вещь или доказательством точного DPS. Игрок не должен вручную собирать такие документы: автоматический source-bound нормализатор этих входов остаётся отдельной задачей. Реальные сценарии и отчёты хранятся в ignored local-data, публичные примеры — синтетические.

Для сравнения после topology и защиты цели есть отдельный [combatupgrades](COMBAT_UPGRADES.md) с общими target/uptime. Он также требует полных исходных сценариев и не восстанавливает их автоматически из вещей.
