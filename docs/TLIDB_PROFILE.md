# Профиль Chromatic Shot из сохранённой страницы TLIDB

`damage_lab.tlidbprofile.profile` извлекает таблицу навыка из байтов одной
сохранённой страницы. Это библиотека справочных данных для расчётного ядра.
Она не обращается к сети или игре и не выбирает версию данных персонажа.

```python
import hashlib
from pathlib import Path

from damage_lab.tlidbprofile import profile

data = Path("local-data/chromatic.html").read_bytes()
result = profile(
    data,
    hashlib.sha256(data).hexdigest(),
    source_url="https://tlidb.com/en/Chromatic_Shot",
)
```

Переданный SHA-256 связывает результат с точными входными байтами. Если нужна
проверка против ранее принятого файла, передавайте его заранее сохранённый хеш.
Вычисление хеша того же файла непосредственно перед вызовом само по себе
не подтверждает источник или неизменность относительно прежнего наблюдения.
URL — декларация вызывающего кода: `urlMeaning` явно сохраняет это ограничение.
Полные ответы сайта, HTTP-заголовки и результаты храните в ignored-каталогах.

## Что сохраняется

- Название и ID навыка, наблюдаемые отметка сезона и уровень заголовка
- Base damage, effectiveness и shotgun coefficient отдельно для заголовка
  и каждой собственной строки таблицы; описания количества снарядов — в строках
- Исходные числовые строки; процент также представлен точной десятичной дробью
- Byte/character spans каждой строки, SHA-256 и размер исходного тела
- Явные пропуски собственной effectiveness или shotgun coefficient

Отсутствующее значение остаётся `null`: заголовок или предыдущая строка его
не заменяют. Количество фактических попаданий не выводится из двух описаний
количества снарядов. Cast Speed остаётся показанной частотой с неизвестной
точностью; обратная величина не объявляется точным временем каста.

## Проверка структуры и пределы

Поддержана одна структура страницы Chromatic Shot, ID 7007: единственные
заголовок навыка, карточка Info, карточка описания и карточка Progression со
связанной таблицей. Строки должны иметь уникальные последовательные уровни
от 1 и соответствовать заявленному положительному количеству.

Размер входа ограничен 4 MiB, дерево — 20 000 элементов и глубиной 128,
таблица — 64 строками, строка таблицы — 8192 символами,
отдельный тег — 4096 символами. Скалярный элемент ограничен 288 символами
до обработки, включая его закрывающий тег. Это технические пределы, а не максимальный
уровень навыка в игре. Неоднозначные атрибуты, неподдержанная разметка значений,
скрытые значения в комментариях и некорректные числовые роли вызывают
`ProfileError` с фиксированным кодом без копирования входного текста.

Изменение сайта может потребовать нового адаптера. Отказ не превращается
в пустой профиль, нулевой урон или выбор первого подходящего фрагмента.

## Проверенное сохранённое тело

23 октября 2026 года библиотека проверена на сохранённом UTF-8 ответе размером
65 706 байт, SHA-256
`44ce3e8daad17468370a8dba5e43f6ce755578d1da4e78389e61bcf16ac7f786`.
Получены 40 строк; у уровней 21–40 нет собственной effectiveness. Byte spans
каждой строки декодируются точно в соответствующий character span.
Само тело и полученный профиль остаются локальными.

## Граница расчёта

`runtimeVersion = "unknown"`, `effectiveLevel = null`, `arithmeticReady = false`.
Профиль содержит опубликованный текст; его применение требует отдельного
контракта версии игры, effective level и правил параметров. Таблица с плоским
хвостом не даёт основания интерполировать отсутствующую effectiveness или
отменять отдельное post-20 scaling.

Сопоставление официального дополнения и двух вариантов SS14 описано в
[свидетельстве об изменениях Chromatic Shot](research/chromatic-patch-witness.md).
Этот адаптер не меняет импорт персонажа, прежние формулы или итоговый DPS.
