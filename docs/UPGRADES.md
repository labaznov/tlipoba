# Условное сравнение улучшений

`damage_lab.upgrades.evaluate(document)` сравнивает нормализованные варианты в одной модели урона. Это чистая библиотечная функция без сети, доступа к игре, рынка и записи файлов. Она создаёт независимый отчёт `tli-upgrade-report-v1`; результат всегда `conditional`.

Это интерфейс разработчика для будущего автоматического нормализатора предметов. Игрок не должен вручную переписывать характеристики или составлять такие сценарии. Подбор настоящего снаряжения пока невозможен без подтверждённого импорта его эффектов, взаимодействий и цен.

## Вход

Формат `tli-upgrade-scenario-v1` требует ровно `format`, `panel`, `condition`, `combat`, `currency`, `candidates`. Неизвестные поля отклоняются. `currency`, `id`, `name` и записи candidate `missing` — непустой текст без пробелов по краям. Идентификаторы кандидатов уникальны.

- `panel`: обязательны `cast_rate`, `max_tangles`, `extra_attachments`, `cold_penetration`; при `basis: "panel"` также `spell_dps`, при `basis: "hit"` — `hit_min`, `hit_max`, `crit_chance`, `crit_multiplier`. Разрешены только эти поля и необязательное `armor_penetration`. Все переданные значения проверяются, даже если выбранная база их не использует
- `condition`: ровно `basis`, `active`, `hits`, `retention`, `lucky`, `critical_more`, `resistance`, `taken`, `uptime`. Семантика — существующий [условный расчёт](INPUTS.md); общий объект используется для всех вариантов
- `combat`: полный существующий [боевой контекст](COMBAT.md), включая `reference`, `target`, броню, tick-гипотезу, неизвестные эффекты и пояснения. Его проверяет `combat.apply`
- `candidates`: массив объектов с ровно `id`, `name`, `target`, `cost`, `missing`. `target` содержит полные массивы `damage`, `cast`, `taken` по контракту `combat.apply`; `cost` — конечное неотрицательное число либо `null`, когда цена неизвестна; `missing` — явный массив неучтённых эффектов, включая пустой

Счётчики требуют целых значений, булевы вместо чисел не принимаются. Границы совпадают с поддерживаемым engine: cast rate 0–1 000 000; max Tangle 0–4; extra attachments, active и hits 0–1000; DPS и hit damage 0–10¹⁸; crit chance, armor penetration, retention и uptime 0–1; crit multiplier 0–100; cold penetration 0–10; resistance −10–1; critical more −1–100; taken −1–100. `active` не может превышать max Tangle. Переданный hit range обязан быть упорядочен. `lucky` — строго булево значение.

## Замена полного пула

Базовый результат равен `apply(panel, calculate(panel, condition), combat)`. Для кандидата меняется **только** `combat.target`; панель, reference, условия, броня, tick-гипотеза и фиксированный Carino-контекст общие. Candidate-specific panel/context overrides не разрешены.

`reference` описывает модификаторы, уже учтённые в исходной панели. И baseline `target`, и каждый candidate `target` описывают полный соответствующий пул поддерживаемых эффектов. Отношение target/reference выполняет существующая библиотека. При замене предмета нужно сохранить неизменные эффекты в новом пуле, убрать старые строки и добавить новые; передавать только новые бонусы поверх панели нельзя.

Синтетический пример: панель 1000 DPS уже включает общий affix с прибавками 0,25 и 0,15. Его фактор 1,4. Baseline сохраняет обе строки, а candidate заменяет их одной прибавкой 0,75 с фактором 1,75. При остальных нейтральных условиях candidate даёт 1250 DPS и delta 250, а не повторное умножение панели на 1,75. Это арифметика явно выбранных пулов, не доказательство игровой применимости такого affix.

## Отчёт и рейтинг

Отчёт сохраняет полный detached `scenario`, baseline с trace/assumptions, кандидатов и `ranking` — массив IDs для сравнения стоимости. `price_source: "caller"` означает, что цены предоставил вызывающий код; это не рыночные данные.

Для каждого кандидата возвращаются `dps`, `delta = candidate − baseline`, `relative = delta / baseline`, `cost`, `per_cost = delta / cost`, `gaps`, два флага eligibility и полный условный `result`. При нулевом baseline `relative` равен `null`; при неизвестной или нулевой цене `per_cost` равен `null`. Переполнение и потеря ненулевого частного до нуля отклоняются; Infinity в рейтинге отсутствует. Модель не округляет DPS для совпадения с панелью.

| `status` кандидата | Значение |
| --- | --- |
| `incomplete` | Есть shared либо candidate coverage gaps; числовая часть сохранена только как неполный сценарий, рейтинги запрещены |
| `not_upgrade` | Поддерживаемый delta неположителен |
| `unpriced` | Delta положителен, явных gaps нет, цена неизвестна; `eligible_for_ranking` истинен, `eligible_for_cost_ranking` ложен |
| `free` | Положительное изменение при явной цене 0; допускается в рейтинг без деления на ноль |
| `upgrade` | Положительное изменение с известной положительной ценой и без явных gaps |

Это классификация сценарного изменения, а не подтверждение механики или рекомендация купить предмет. Даже пустой `missing` не меняет `conditional` на точный результат. Все базовые модельные ограничения, включая Tangle inheritance и shotgun assumptions, остаются в `result.assumptions`.

Из рейтинга исключаются неполные, неположительные и неизвестные по цене варианты. Сначала идут положительные бесплатные варианты, затем платные по убыванию delta/cost; равенство разрешается меньшей ценой, затем ID. Для бесплатных вариантов при равной цене порядок задаёт ID. Входной порядок списка кандидатов не используется как скрытый приоритет.

## Использование API

Воспроизводимый пример из корня проекта:

```powershell
python -m examples.compare_upgrades
```

Все числа, пулы и цены в `examples/upgrades.json` вымышлены. Пример показывает baseline 1000, варианты 1250 и 1500 DPS и порядок `budget`, затем `larger`: меньший вариант даёт больший прирост на единицу своей сценарной цены. Это проверка арифметики, а не предложение покупки.

```python
import json
from pathlib import Path
from damage_lab.upgrades import evaluate

document = json.loads(Path("synthetic-upgrades.json").read_text(encoding="utf-8"))
report = evaluate(document)
print(json.dumps(report, ensure_ascii=False, allow_nan=False, indent=2))
```

`damage_lab.upgradereport.render(report)` возвращает автономный HTML с общими условиями, таблицей вариантов, рейтингом и раскрываемой трассировкой. Он показывает явные цены вызывающего кода, отдельные случаи бесплатного варианта и неизвестной цены, а также пробелы и допущения. Неизвестные дополнительные поля не выводятся. Запись HTML остаётся задачей вызывающего кода; реальные отчёты хранятся локально.

Готовый сценарий можно сохранить одной командой из корня проекта:

```powershell
python -m damage_lab upgrades --scenario examples/upgrades.json --output local-reports/upgrades-example
```

Команда создаёт `upgrades.json` и `index.html` в новом каталоге, без SQLite. Вычисления и цены совпадают с библиотечным API; рыночные данные не запрашиваются. Это тот же синтетический пример, а не автоматический подбор реальных предметов.

Вход ограничен 8 МиБ и должен быть UTF-8 JSON, с BOM или без него; повторяющиеся поля и неконечные числовые константы запрещены. Существующий файл или каталог результата не перезаписывается. Родительская папка создаётся автоматически; на Windows результат публикуется переименованием подготовленного временного каталога после записи обоих файлов. При ошибке команда возвращает 1 и не оставляет частичный результат; содержимое входа в сообщение ошибки не включается.

Вычислительная библиотека и HTML-рендерер не сохраняют файлы самостоятельно; файловый интерфейс находится в `damage_lab.upgradecli`. Реальные входы и полученные отчёты должны храниться в ignored local-data, а публичные примеры — содержать только синтетические данные. Неизвестные affix bindings, эффективные уровни, conditional effects, uptime, стоимость и актуальная топология боя остаются задачами автоматического импортёра; библиотека их не угадывает.

Локальная проверка: `C:/Python313/python.exe -m unittest discover -s tests -p test_upgrades.py -v`.
