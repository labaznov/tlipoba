# Привязка кода билда к сохранённым данным

Проверено 2026-10-22 по существующим снимкам и коду экспортёра; обращения к игре и сетевых запросов не было. Частные коды, имена и идентификаторы экземпляров не публикуются.

## Что подтверждено

Канонический код декодируется в 16 байт. Исследованные примеры имеют структуру UUIDv1; это наблюдение, а не контракт всех кодов игры. Время UUID является кандидатом времени идентификатора. Оно не доказывает время содержимого билда, актуальность экипировки, допустимый возраст кода или срок его действия. Другие версии UUID нельзя отклонять только на основании этих примеров.

Сохранённый BD-дескриптор содержит код и краткое описание. В одном примере его секундное время совпало с временем UUID после отбрасывания дробной части; другие поля совпали с героем и тремя навыками страницы. Это кандидаты сопоставления. Дескриптор не содержит весь билд.

В исследованных ServerSource-пэйлоадах не найдено кода или названия билда. Их поля определяют персонажа автора; сами по себе они не доказывают, к какому коду относится ответ. Для текущего адаптера связь идёт через контроллер страницы, содержащий код и ссылку на данные. Сравнение введённого кода с сохранённым полем проверяет заявление снимка, но не превращает файл в независимо удостоверенный свежий ответ сервера.

Сохранённые флаги просмотра показывают только разрешённый просмотр в исследованных примерах. Значения IsOldData не сохранялись. Версия данных аффиксов не является временем снимка. Старый пример с проверенным кодом не содержит ServerSource; более поздние полные источники не проходили эту проверку кода. Их нельзя объединить в одно доказательство идентичности.

## Что требуется для загрузки по коду

Не установлены запрос и его поля, транспорт и обрамление сообщения, требования сессии, конверт ответа и правила корреляции, семантика свежести и жизненный цикл кода. Символы ожидания сети и UI-функции не определяют endpoint. Share API планировщика Compendium не является API игры.

Полезный ближайший блок — чистая оценка сохранённого снимка: каноничность кода, явно заявленная связь, разрешение просмотра, форма обязательных секций и противоречия источников. Недостающий флаг отличается от запрета просмотра. Несовпадающий код отличается от отсутствующей проверки. Транспорт, идентичность пэйлоада и свежесть остаются неподтверждёнными; будущее время UUID даёт предупреждение, а не выдуманное правило отказа.

Это продолжение [исследования импорта](build-import-api.md). Оценка сохранённого источника и [аудит состава и эффективного состояния](import-state-provenance.md) дополняют друг друга; ни один из них не загружает билд из неизвестного API.
