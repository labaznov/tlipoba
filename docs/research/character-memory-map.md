# Карта извлечения персонажа из памяти

Проверено по коду внешнего Windows-экспортёра и структуре сохранённого снимка
2026-10-22. Это карта доступных структур билда и правил чтения. Неизвестные поля
остаются задачами извлечения; они не заменяются ручной анкетой игрока.

## Путь до состава билда

| Участок | Проверенная структура | Ограничение |
| --- | --- | --- |
| Поиск | Строка класса `ViewPlayerBDReferenceCtrl` → Lua-ссылки на неё → владеющая таблица | Поиск ограничен читаемыми `MEM_PRIVATE` регионами и бюджетами |
| Контроллер | `__ClassName`, `BDName`, `BDAuthorName`, `BDID`, `ViewPlayerData` | `BDID` — сохранённое утверждение контроллера; совпадение кода не подтверждает идентичность пэйлоада |
| Корень страницы | `ViewPlayerData` с таблицами разделов | Ссылки корня и anchors перепроверяются; это не атомарный снимок живой памяти |
| Представление Lua | nil, bool, float64, integer, string, tableRef; неизвестные теги непрозрачны | Функции, userdata и ленивые metatable-поля не исполняются |
| Предметы | `WearItems` → обёртка `_Raw_Data` → `ConfigBaseId`, `Level`, аффиксы и серверная копия | Наличие ролла отдельно от его подтверждённого математического смысла |
| Навыки | `Skills` хранит предметы навыков; `SkillLayout` связывает основные навыки и поддержки | Уровень камня, эффективный уровень, установка и активация различаются |
| Нативные поля уровней | `ServerSource.data.featuresInfo.skills.skills[i]`: `Level`, `SkillItemLevel`; точная уникальная связь `Id` с клиентским экземпляром | Наблюдаемые integer-поля сохраняются отдельно; их смысл и включение прибавок не подтверждены |
| Таланты | `GeniusInfos` и серверные данные талантов | Ранг и максимальное число очков нельзя отождествлять без проверки поля |
| Герой | `HeroCharacter`, `HeroCharacterItems` и серверный обзор свойств | Прямое подтверждённое поле итогового ранга свойства пока отсутствует |
| Пакты | `PetDatas` и серверные данные контрактов | Установленный объект не подтверждает действие всех его эффектов |
| Серверные параметры | `ServerSource.attrInfo`: `rpc.ViewPlayerAttrInfo` с бинарной нагрузкой | Только отдельные поля сопоставлены наблюдениями; универсальная схема не восстановлена |

Код, подтверждающий цепочку, находится во внешнем проекте:
`discovery.py` (`chunks`, `table_owners`, `inspect_controller`, `discover`),
`native_layout.py` (`Inspector`) и `native_export.py` (`capture_controller`,
`capture_open`). Публичный потребитель находится в `damage_lab/archive.py`,
`damage_lab/logstats.py`, `damage_lab/installedskills.py` и связанных модулях.
Внешний экспортёр пока не включён в публичный репозиторий.

Для повторного поиска проверен [приватный офлайн-прототип с cache S/R](cached-discovery.md).
Он пересчитывает владельцев по свежему census и сохраняет отказы при пропусках
чтения. В живой импорт он ещё не подключён; эквивалентность ограничена неизменным
образом памяти и не подтверждает идентичность объектов или атомарность.

Обычный поиск внешнего экспортёра теперь использует [общий бюджет чтений и
census](discovery-read-budget.md), включая вложенную проверку кандидатов.
Исчерпание прерывает весь поиск, сохраняя проверку единственности; лимит
не распространяется на последующий захват разделов. Живая проверка этой
интеграции ещё не выполнена.

На нативном уровне экспортёр теперь сохраняет [типизированный результат
неполного чтения](native-read-outcomes.md): отказ, короткий успех или аномальный
счётчик, без подстановки вымышленного кода ошибки. Сырая `.outcome` остаётся
локальной; прямое RPC-чтение сохраняет проверенную проекцию. Сводная диагностика
пропусков поиска ещё не реализована.

Внешний адаптер также выполняет [офлайн-сверку нативных уровней с видимыми
строками журнала](log-native-level-witness.md). Два сохранённых события
подтвердили наличие `Id`, `Level` и `SkillItemLevel` в видимой части
`skills.skills`; соответствие записей не устанавливает текущего персонажа
или effective level. [Companion подключён к обычному импорту tlipoba](../BUILD_WITNESS.md):
consumer проверяет ссылки на байты и безопасную схему, а соединения сохраняет
как `producer_reported`. Диагностика проходит через JSON, SQLite и пассивные
отчёты; effective level и DPS из этих сравнений не выводятся.

Resolver `0.4.0` сохраняет эти нативные поля для каждого однозначно установленного
skill ID, а bundle `0.2.0` переносит их в обычный импорт. `native_level_fields`
содержит путь исходной строки, тип каждого поля и сравнение `Level` с gem level.
Неоднозначная связь не выбирает первый экземпляр; отсутствие данных не заменяется
нулём. Ни совпадение, ни различие полей не выводит effective level. Подробности
контракта — в [описании кандидатов уровней](../LEVEL_CANDIDATES.md).

## Отдельное наблюдение одного нативного поля

Во внешнем экспортёре добавлен экспериментальный `candidate_path.record`:
`ViewPlayerData → SkillLayout → array[tab] → array[row] → SkillData → _Raw_Data →
ServerPlayerItem → SkillItemLevel`. Индексы относятся к физическим native array
slots. Связь с экземпляром навыка потребует дополнительного наблюдения instance ID
и отдельного адаптера; само integer-поле не устанавливает effective level.

Диагностика требует кандидата после полного проверенного поиска как внешнее
условие. Она сверяет точные пять ключей контроллера, класс, заявленный `BDID`,
ссылку корня и выбранные переходы. После чтения поля повторно проверяются
заголовки, slots и соответствующие строки. Изменённый заголовок отвергается
до обращения по его новым указателям. Равенство наблюдений не доказывает
атомарность, глобальную единственность или выбранный игроком билд.

Общий бюджет этого отдельного вызова — до 96 чтений и 1 МиБ запрошенных байтов,
по 64 КиБ за чтение, включая неудачные попытки. Предел времени 2 секунды мягкий:
нужен внешний таймаут. Фактические изменяемые параметры бюджета и нулевые
счётчики проверяются при входе; вызывающая сторона не должна менять их во время
чтения. Минимальный синтетический путь занял 68 чтений; стоимость настоящего
билда остаётся неизвестной. Лимиты обычного поиска не расширялись.

Приватная запись существует только в памяти одного процесса и хранит точные
объекты reader и endpoint. Fingerprint, PID и expiry — метаданные, а не
доказательство идентичности backend. В публичной сводке остаются счётчики.
Код прошёл независимый review, проверки на синтетической памяти и полный набор
из 996 тестов Windows-экспортёра с одним пропуском. В обычный живой экспорт эта
диагностика ещё не подключена; новые показатели Carino и точный DPS не получены.

Отдельный opt-in `record_identity` дополнительно наблюдает `ItemId` строки навыка
и её `_Raw_Data` в тех же проходах. Проверяются нативный тип, 1–256 байт строгого
UTF-8 и точное совпадение значений; после чтения поля повторно сверяются оба
слота, ключа и значения. Требование двух ID — консервативная политика прототипа,
а не подтверждённое правило игры. Отсутствие остаётся пробелом, конфликт или
дублирующийся ключ дают отказ. Минимальный синтетический путь занял 82 чтения;
обычный `record` сохранил 68. Проверены независимые синтетические случаи и набор
из 1006 тестов экспортёра с одним пропуском.

Последующий офлайн-модуль внешнего экспортёра `source_request` получает физические
индексы и приватный ID экземпляра из исходных байтов экспорта. Он сверяет SHA-256,
пересчитывает inventory и сравнивает его с переданным отчётом с сохранением типов;
ручные native-индексы и ID не нужны. Неоднозначный экземпляр не выбирается.
`matches` сравнивает подготовленный запрос с `record_identity`, сохраняя все
утверждения о выбранном билде, актуальности и атомарности неподтверждёнными.

До разбора действуют пределы 8 МиБ для source, 1 МиБ для отчёта, глубина 64,
300 000 структурных токенов, 65 536 контейнеров и 128 байт одного нестрокового
scalar. Это инженерные лимиты: более крупный допустимый билд даст явный пробел.
Ограничены также физические slots, строки и канонический вывод. Публичные объекты
проверяют точные типы до сравнений; изменённый detached `shapes` не меняет запрос.

Проверены полный синтетический пакет с искусственной памятью, 15 независимых
случаев и набор из 1057 тестов экспортёра с одним пропуском. На сохранённом
экспорте Carino подготовка запроса для первого наблюдаемого основного навыка
завершилась без ручных индексов. Это исторический файл: новый живой снимок,
effective level и точный DPS не получены. В обычный живой экспорт модуль пока
не подключён; совпадение ID не доказывает общий момент захвата или текущую панель.

## Где искать недостающие входы DPS

Указанные ID относятся к журналу панели. Они **не являются** установленными
идентификаторами бинарных полей `attrInfo`. Потребитель проверяет их отдельно
в `damage_lab/logstats.py`; связь панели с выбранным билдом остаётся неизвестной.

| Вход | Автоматический источник | Что остаётся проверить |
| --- | --- | --- |
| Диапазон spell hit | Журнал: `11800`, Total Spell Damage | Идентичность навыка, состояние панели и смысл диапазона относительно крита |
| Частота каста | Журнал: `21000` | Состояние персонажа и наследование Tangle |
| Шанс крита | Журнал: `21212`, проценты → доля | Состав пула, Lucky и условия боя |
| Критический множитель | Журнал: `21400`, проценты → множитель | Additional critical damage отдельно от полного множителя |
| Максимум Tangle | Журнал: `21714` | Максимум отдельно от количества реально действующих Tangle |
| Дополнительные прикрепления | Журнал: `21715` | Прикрепления отдельно от числа попаданий в одну цель |
| Пробивание холода | Журнал: `11000`, проценты → доля | Сопротивление цели и условия применения |
| Панельный Spell DPS | Журнал: `10103`; отдельное сопоставленное поле native `1.10` | Семантика панели отдельно от итогового боевого DPS |

В сохранённой структуре памяти именованные поля диапазона hit, частоты каста,
крита и Tangle пока не найдены. Это не доказывает их отсутствие в процессе:
они могут находиться в другой структуре или непрозрачном бинарном сообщении.
Поля `ServerSource.version` пока не привязаны к версии клиента и каталога.

## Достоверность и нагрузка

Ошибки чтения chunk-прохода теперь останавливают поиск в экспортёре. Ошибки I/O
и короткие чтения при проверке строк, ссылок и владельцев также останавливают
выбор кандидата. Обнаруженные изменения структуры и превышение бюджета проверки
пока могут классифицироваться как структурное отклонение; это остаётся пробелом
различения нестабильного и неподходящего кандидата.
Сохранённые старые пакеты tlipoba принимает с явным предупреждением:
`complete: true` не перекрывает ненулевой `readFailures`.

После перезапуска адреса требуют нового поиска. В текущем проверенном алгоритме
каждый экспорт выполняет discovery; проверка ранее найденных anchors не исключает
появление второго контроллера в том же процессе. Успешные чтения не доказывают
неизменность всей кучи между проходами.

Пользователь разрешил пассивное чтение во время игры. Общий лимит — одна тяжёлая
локальная задача, ограниченные объём и время; управление интерфейсом требует
отдельного окна, когда пользователь не играет. Постоянные полные сканирования
не являются целевым режимом импортёра.

Экспортёр теперь сохраняет уже прочитанные скалярные поля корня в `pageScalars`,
включая `IsOldData`, `FeatureStatus`, `DisplayBoxStatus`, если они присутствуют.
Сохраняются bool, int, конечный float и строки до 256 байт UTF-8; неподдержанные
значения остаются непрозрачными. Таблицы остаются разделами. Тест сравнивает
последовательность чтений с вариантом без этой проекции: дополнительных чтений нет.
Имена полей пока не дают права автоматически объявлять билд свежим или активным.
В старом сохранённом снимке новых скаляров нет. Следом нужны сопоставленные
автоматические наблюдения панели и `attrInfo` при
контролируемом изменении одного параметра, чтобы восстановить новые поля схемы.

## Ожидание ответа локального reader

Клиент внешнего экспортёра теперь использует один monotonic deadline для
ожиданий приёма в обеих фазах аутентификации. Проверка Windows/CPython 3.13
выполняется до открытия handle; runtime вне этого контракта получает явный отказ.
При сбое открытое соединение закрывается. Закреплённый Endpoint и формат
request/reply сохраняются; production threads или процессы не добавлены.

В ограниченном опыте с локальным тестовым pipe прежний stdlib Client оставался
заблокированным через две секунды после принятия соединения и завершился только
после закрытия peer. Новый клиент с receive budget в одну секунду вернул timeout
примерно через 1,02 секунды после принятия; peer подтвердил закрытие клиента.
Оба дочерних процесса и тестовые peer threads завершились. Это наблюдение одного
сценария на CPython 3.13.3, а не верхняя граница длительности всех операций.

Отправки, cancel drain и завершение чтения после сигнала не имеют общего жёсткого
deadline. Connect использует собственный цикл stdlib; абсолютное ограничение
живого захвата по-прежнему требует внешнего управляемого процесса. Silent client
может блокировать серверный worker: исправление относится только к клиентскому
ожиданию аутентификации. Сама игра в этом опыте не использовалась.

## Поиск ссылок с ограниченной памятью

Внешний экспортёр теперь группирует 12-байтовые шаблоны ссылки по общему
8-байтовому суффиксу. После поиска суффикса проверяются все 12 байт; выравнивание
проверяется по абсолютному адресу. Поиск сдвигается на один байт и сохраняет
совпадения около границ chunk благодаря существующему хвосту.

До выдачи результатов одного буфера сохраняется не более 65 536 кандидатов.
Если число совпадений суффикса превышает лимит, накопленные кандидаты
отбрасываются и весь текущий буфер обрабатывается прежним потоковым поиском
по каждому шаблону. Следующие буферы этого прохода также идут через потоковый
вариант. Результаты fallback не упорядочены; потребитель собирает проверенные
ссылки в множество и сортирует их перед поиском владельцев.

Дополнительная память поиска ограничена `O(cap + P)`, где `P` — число шаблонов;
это не материализация всех совпадений плотного буфера. Сортировка ограниченного
списка требует дополнительного списка ссылок. Ограничения объёма чтения, числа
контроллеров и отказ при ошибках чтения сохраняются. Ускорение на синтетических
данных не является измеренным ускорением в игре.

Проверены равенство множеств результатов, границы буфера, ложные суффиксы,
невыравненные совпадения, плотные буферы, принудительный fallback и ранняя остановка
потребителя. Полный перекрывающийся 12-байтовый decoy остаётся рекомендуемым
дополнительным регрессионным случаем; prefix noise не заменяет такую проверку.

## Где пока не видны имена классов

Инвентаризация одного сохранённого снимка проверила точные ключи `__ClassName`
в захваченных графах разделов страницы: таких ключей не найдено. Контроллер
расположен выше корня страницы и не входит в эту выборку. Часть заголовков
содержит указатели на метатаблицы, но их содержимое раньше не читалось.

Это ограниченный отрицательный результат для графов одной страницы. Он не
доказывает отсутствие классов или менеджера параметров в процессе. Маркер журнала
`RoleAttrMgr@` также не устанавливает имя Lua-класса. Менять строку класса в
существующем `discover` недостаточно: `inspect_controller` проверяет конкретные
поля контроллера билда и отверг бы другой тип объекта.

## Поверхностные метаданные типов

Следующий обычный захват также сохраняет диагностический раздел `metatables`:
только непосредственные метатаблицы контроллера и корня страницы. Общий лимит —
64 КиБ запрошенных байтов, включая заголовок контроллера и неудачные попытки
чтения. Это счётчик нагрузки, а не точное число успешно полученных байтов.

Каждая уникальная метатаблица декодируется новым `Inspector` при общем бюджете.
Повторный указатель использует только завершённый результат, включая пробел,
без скрытого повтора чтения. Частично прочитанный кэш одного объекта не может
превратить ошибку другого в успешный результат.
Статусы различают прочитанные метаданные, отсутствующий указатель, недоступный
адрес старого кандидата и пробел из-за I/O, структуры, бюджета или числа строк.
Нормальные разделы билда при диагностическом пробеле сохраняются.

Успешный результат содержит не более 128 строк; ключи и строковые значения
ограничены 256 байтами UTF-8. Другие значения остаются непрозрачными. Это лимиты
вывода; чтение строк и hash-слотов также ограничивает общий бюджет. Цепочки
`__index` и вложенные метатаблицы не обходятся, функции Lua не вызываются,
указатели и бинарные значения в сводку не попадают.

Метаданные отражают локальное наблюдение указателей; их неизменность на протяжении
всего захвата не доказана. Сам Windows API описывает копирование заданного
доступного диапазона памяти; из этого не следует согласованность всех структур
билда в один момент. Это ограничение нашего вывода из
[контракта ReadProcessMemory](https://learn.microsoft.com/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory),
а не утверждение о внутренней реализации игры или API.

Живая проверка после этих изменений обнаружила пропуски чтения на первом проходе
и остановилась до создания нового снимка. Причина недоступности участков ещё
не установлена; повторные полные сканы и ослабление проверки единственности
кандидата не выполнялись.

## Ограниченная живая диагностика

Отдельная утилита внешнего экспортёра `memory_probe.py` использует только
существующие операции чтения и списка регионов. Лимиты: 256 запросов, включая
начальный и конечный списки регионов, не более 16 МиБ запрошенных байтов и 64 КиБ
за одно чтение. Ошибки также списываются из бюджета; повторов и дробления
неудачного чтения нет. Сами байты памяти не сохраняются. Адреса и ошибки остаются
в приватном файле, общая сводка содержит агрегированные счётчики, лимиты и статусы.

Неудачный образец также сохраняет приватную повторно проверенную нативную
диагностику, если сервер её сообщил; иначе результат остаётся `unknown`.
Это относится к одному вызову, а не к полноте поиска. Публичная схема и квоты
не меняются. См. [результаты чтения и границы проверки](native-read-outcomes.md).

Десятисекундный бюджет проверяется между вызовами, включая вызов конечного списка
регионов. Это не жёсткий предел длительности одного RPC: запуск живой проверки
дополнительно ограничен внешним таймаутом 35 секунд. Неожиданные ошибки программы
не превращаются в якобы недоступную память; ожидаемые ошибки сеанса и транспорта
дают отдельные диагностические результаты.

Одна живая проверка завершилась за 0,641 секунды снаружи процесса: 254 успешных
чтения, 6 316 032 запрошенных байта, ноль ошибок и коротких чтений. Два списка
регионов совпали как наблюдения. Лимит запросов остановил выборку на префиксах
ранних регионов: внутренние участки и большая часть кучи остались непроверенными.
Поэтому этот результат не объясняет пропуски полного поиска и не доказывает
неизменность карты между наблюдениями.

Независимая проверка обнаружила и воспроизвела на синтетическом конфиге возможную
смену endpoint: старый клиент перечитывал конфиг перед каждым RPC. Доказательств
такой смены в выполненной живой проверке нет; счётчики байтов и запросов остаются
наблюдениями, но сами по себе не связывают их с одним сеансом.

`RemoteReader` и диагностический `SessionReader` теперь используют один закреплённый
`Endpoint`: конфиг проверяется при создании, expiry проверяется перед каждым
запросом, замена файла не переключает транспорт и не продлевает срок действия.
Все операции одного клиента используют тот же endpoint; ошибки не запускают
fallback или повтор. Ключ не попадает в `repr`, ошибки или диагностический вывод.
Обычный одноразовый `call` сохранён для status/close. Изменения прошли TDD,
независимый review и полный набор из 623 тестов внешнего экспортёра.

Отсутствующий, истёкший или некорректно типизированный конфиг при запуске диагностики теперь даёт
контролируемый отказ без RPC и без каталога результата; существующий каталог
имеет приоритет и не перезаписывается. Это закрепление клиентского транспорта,
а не доказательство идентичности объектов игры или атомарности. Connect и
authentication handshake по-прежнему требуют внешнего таймаута для общего
ограничения времени. После изменений новый живой захват не выполнялся.

Экспортёр теперь останавливает поиск сразу на первом ошибочном или коротком
чтении chunk, сохраняя приватный контекст исходного региона, смещения, размера,
прохода и метку времени списка регионов. Следующий chunk и следующий проход
не запускаются. Ошибки проверки кандидатов учитываются отдельным прежним
механизмом: это не остановка на любой ошибке I/O во всём поиске.

Изменение проверено 581 тестом экспортёра и независимым review. Оно требует
обычного нового ReaderSession, поскольку модуль поиска кэшируется процессом;
живой поиск после изменения ещё не запускался. По старому агрегированному числу
ошибок нельзя восстановить исходные адреса. Диагностика конкретного нового
пропуска остаётся отдельным ограниченным действием, без автоматического
повторения полного поиска. Полнота импорта и точный DPS не подтверждены.

Отдельная операция внешнего ReaderSession `native_sample` теперь сравнивает
нативные чтения 64 КиБ и 4 МиБ в начале не более трёх регионов из нового списка.
Обход метаданных ограничен 65 536 попытками получения следующего региона,
включая попытку EOF; для текущего `ProcessReader` это верхняя граница числа
`VirtualQueryEx`, а не точный счётчик. Без своевременно полученного EOF чтения
данных не начинаются. Лимит данных — шесть попыток и 12 779 520 запрошенных байтов,
включая ошибки; прежний клиентский `read` сохраняет предел 64 КиБ.

Мягкий предел 2 секунды проверяется вокруг вызовов и перед возвратом результата;
последнее наблюдение времени перед чтением проверяется до списания бюджета.
Текущий нативный вызов отменить нельзя. Истечение сеанса, его закрытие или
таймаут клиента сами по себе не доказывают прерывание вызова либо завершение
worker. Ответ содержит счётчики и фиксированные исходы, без адресов и байтов;
полнота карты, найденный корень и текущий персонаж не подтверждаются.

Операция прошла независимый review, девять отдельных проверок на искусственном
reader и полный набор из 1056 тестов экспортёра с одним пропуском. Независимые
регрессии воспроизвели ошибки допуска нативной диагностики до исправлений.
Одна живая проверка завершилась за 0,21 секунды: шесть успешных чтений, включая
три по 4 МиБ, без ошибок и коротких чтений. Это префиксы трёх выбранных регионов,
а не проверка всей карты; прежние пропуски полного поиска остаются необъяснёнными.
ReaderSession штатно закрыт после ответа. Новый билд и показатели персонажа
не получены; полный поиск не запускался.

Параллельный офлайн-путь теперь позволяет сохранить source-bound контекст
напечатанных таблиц через `import-log --context`. Это ограниченные окна физических
строк для исследования связи событий, без догадок о сетевом протоколе, ID ответа
или текущем персонаже. См. [контракт и ограничения](../LOG_IMPORT.md).

## Бюджет обычного поиска билда

Внешний экспортёр ограничивает обычную операцию Reader `discover` одним общим
бюджетом: 100 000 вызовов чтения и census, 20 ГиБ запрошенных байтов и 65 535
полученных регионов плюс попытка EOF. Три прохода используют один список регионов;
предел одного прохода — 8 ГиБ, размер нативного чтения — не более 4 МиБ.
Проверки полноты, ошибок валидации и единственности кандидата сохранены.

Мягкий предел 30 секунд проверяется между вызовами и после сборки ответа.
Неудачные чтения также списываются из бюджета. Клиент ждёт ответ `discover`
до 45 секунд; это предел ожидания ответа, а не всего транспорта. Текущий
нативный вызов отменить нельзя; таймаут клиента не доказывает завершение worker.
Прежний публичный Python-путь `discover` сохраняет свой контракт.

При первом непрочитанном chunk поиск останавливается. Приватная ошибка сохраняет
контекст прохода и проверенный исход нативного вызова, если он доступен;
неизвестная причина остаётся `unknown`. Исход сохраняется при передаче ошибки
через RPC. В успешный результат добавлены счётчики и лимиты,
без повышения `selectionVerified`; прежний список кандидатов сохранён.

Изменение прошло независимый review, девять отдельных проверок на искусственном
reader и полный набор из 1076 тестов экспортёра с одним пропуском. До исправления
шесть новых проверок выявляли отсутствующее поведение; три проверки прежнего
контракта уже проходили. Последующий review уточнил структуру тестов и описание
порядка проверки времени, сохранив код поиска.

Одна живая попытка через заново запущенный штатный ReaderSession остановилась
на первом непрочитанном chunk первого прохода за 1,08 секунды снаружи клиента.
Запрос 1 196 032 байта вернул проверенный нативный исход `failed/299`; приватная
ошибка сохранила контекст диапазона и прохода. Счётчики всего поиска и фактическое
число перенесённых байтов в этом ответе отсутствуют. Новый снимок не создан;
достаточность общего бюджета для полного поиска остаётся неизвестной.

В Windows код `299` называется `ERROR_PARTIAL_COPY`. Сам код не устанавливает,
почему запрос не выполнен полностью. Контракт `ReadProcessMemory` требует
доступности всего диапазона; нынешняя карта страниц не доказывает состояние
памяти в момент отказа. Это основание для ограниченной проверки конкретного
диапазона, без пропуска нечитаемых участков или повторного полного поиска.
Источники: [системные коды Windows](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-),
[ReadProcessMemory](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory).

После ошибки отдельный `info` подтвердил, что последовательный worker отвечает;
затем получено штатное подтверждение закрытия, файл сеанса исчез. Эта проверка
закрытия не читала память игры. Управление интерфейсом, захват разделов и поиск
конфигураций не выполнялись. Актуальность персонажа, effective level и точный
DPS остаются неподтверждёнными.

## Проверка конкретного непрочитанного диапазона

Во внешнем экспортёре добавлена отдельная операция `range_probe`: два обхода
метаданных ровно запрошенного интервала, без соседних страниц и полного census.
Каждый обход ограничен 64 запросами. Неполная или нечитаемая начальная карта
не допускает чтения содержимого. Иначе выполняется одно чтение целиком и,
для интервала больше 64 КиБ, неперекрывающиеся части по 64 КиБ с обрезкой хвоста.
Общий максимум — 65 чтений и 8 МиБ запрошенных байтов; повторов нет.

Мягкий предел 2 секунды начинается после штатной проверки образа процесса
и проверяется вокруг вызовов и после сборки ответа. Текущий вызов отменить
нельзя. Ошибочные и опоздавшие попытки учитываются; байты сразу удаляются.
Ответ содержит относительные интервалы, исходы и проверенные нативные счётчики,
без абсолютных адресов, содержимого и текста ошибок. Прежний `read` остаётся
ограничен 64 КиБ; правила поиска и отбора кандидата сохранены.

Проверены 1110 тестов экспортёра с одним пропуском и десять независимых
синтетических случаев. Восемь случаев выявляли отсутствующую возможность
на сохранённом предшественнике, два проверяли прежние ограничения.
Одна живая проверка выполнена 2026-10-23 после подтверждённого нового запуска
ReaderSession пользователем. Запрашивался только прежний интервал размером
1 196 032 байта; профиль ограничивал его двадцатью чтениями, 128 запросами
метаданных и 2 392 064 запрошенными байтами. Полный поиск не запускался.

Оба наблюдения карты показали 393 216 байт `MEM_COMMIT`/`PAGE_READWRITE`
и следующие 802 816 байт `MEM_RESERVE` с protect 0. Четыре запроса метаданных
завершились; операция вернула `unreadable` до чтения содержимого. Вызовов
`ReadProcessMemory` и запрошенных байтов было ноль. После отдельного ответа
последовательного worker получено штатное подтверждение закрытия ReaderSession;
файл сеанса исчез, диагностический дочерний процесс завершился.

Эта карта относится к новому наблюдению, а не моменту прежней ошибки `299`.
Она не объясняет прошлый отказ, не доказывает неизменность адресов, атомарность
или текущего персонажа. Новый снимок не создан; полный импорт и точный DPS
остаются неизвестными. Правила отбора кандидата не ослаблялись, пропуски не
обходились и повторного полного поиска не было. Код экспортёра находится
в отдельном локальном репозитории и не входит в этот PR.

## Сохранение уже прочитанных связей

Нативный снимок внешнего экспортёра версии `0.6.0` добавляет два приватных
раздела без дополнительных чтений памяти. `controllerContext` сохраняет
типизированные поля контроллера из результата discovery, а `pageRootContext` —
уже прочитанные записи корневой таблицы страницы, включая нестроковые ключи,
значения массива и адрес прямой metatable. Ссылки на таблицы сохраняются как
диагностические связи; дополнительного обхода по ним нет.

Это разные этапы наблюдения. В discovery поля контроллера уже превращены
в словарь: нестроковые ключи, повторения строковых ключей и массив потеряны.
Новый раздел перечисляет эти потери и не восстанавливает исходную таблицу.
У страницы сохраняется более полная проекция уже прочитанного корня.
Прежние проверки anchors, повторного корня и отказ при повторении строкового
ключа остаются прежними. Равенство проекций не объявляется атомарностью;
нового флага равенства таблиц нет.

Скалярные типы различаются явно. Длинные строки, бинарные данные и значения
NaN/Infinity имеют обозначенные пропуски. Непрозрачная ссылка сохраняет только
тег, без сырого указателя. Большие целые требуют явного точного десятичного
представления при записи JSON. Контракт проверяется после штатного
`guide_model.archive_value`, поскольку обычный `json.dumps` не воспроизводит
все преобразования при создании пакета.

Обычный импорт tlipoba совместим с добавленными полями: они входят в хеш
всего `source.json`, но не проходят семантическую валидацию и не копируются
как содержимое в SQLite, `import.json` или HTML. Сохраняется ссылка на
исходник и его fingerprint. Производные диагностические bundles должны
создаваться заново с хешем новых исходных байтов; добавлять поля к старому
пакету и оставлять прежние связанные хеши нельзя.

Этот блок устраняет потерю уже полученных связей для следующего экспорта.
Он не доказывает доступность глобального контекста `AttrUtils`, актуальность
или выбор персонажа и не создаёт новый живой снимок Carino. Полный импорт,
эффективные уровни и точный боевой DPS остаются открытыми задачами.

## Ограниченный поиск именованного контекста

Во внешнем экспортёре проверен отдельный поиск связи с именем `AttrUtils`.
Его диагностический RPC принимает только имя операции `named_key_owner`;
имя, профиль и лимиты задаёт сервер, а адрес кандидата находит поиск.
До census и чтения содержимого
сохраняются проверки формы запроса, закрытого сеанса и образа процесса.
Обычный экспорт эту операцию автоматически не вызывает.

Фиксированный профиль требует шесть собственных ключей: `SkillStoneId`,
`CurrentAttrShowId`, `MercenaryContext`, `RealCacheList`, `VirtualCacheList`
и `CacheAttrSource`. Это проверка наличия полей, поддержанная путями создания
и сброса в сохранённом исходнике. Она не устанавливает типы значений,
готовность helper, первичный контекст, персонажа или выбранный навык.
Первичный и наёмный контексты могут иметь одинаковый профиль.

Поиск использует общий ограниченный census и три прохода по объявленному
читаемому `MEM_PRIVATE` scope, затем проверяет связи кандидатов. Каждый вызов
получает новый серверный бюджет обычного discovery: 100 000 вызовов чтения
и census, 20 ГиБ запрошенных байтов, 65 535 регионов и мягкие 30 секунд.
Размер chunk — до 4 МиБ, предел одного прохода — 8 ГиБ. После census
проверяются нижние оценки байтов и вызовов для трёх проходов. Если уже они
превышают оставшийся бюджет, операция отказывает до чтения chunks.
Успех этой проверки не гарантирует бюджет на валидацию или достаточное
время; scope не обрезается ради положительного результата.

Проверки ограничивают число строк, ссылок, пар владельцев и попыток проверки
целевых таблиц. Ошибка чтения, неопределённая связь или изменение наблюдения
не становятся доказательством отсутствия либо единственности. Превышение
лимита возвращает отказ без принятого частичного кандидата. Повторные
наблюдения строк, узлов и таблиц проверяют конечный набор связей; их равенство
не исключает ненаблюдаемое изменение и не означает атомарность.

RPC передаёт исходную диагностику одним envelope. Адрес результата остаётся
приватной диагностической связью, без утверждения о каноническом global.
Клиент использует закреплённый Endpoint, не повторяет запрос и ждёт ответ
до 45 секунд. Это ожидание не отменяет серверную операцию и не ограничивает
весь транспорт жёстким дедлайном.

Офлайн-поиск прошёл 51 профильную и 12 независимых проверок координатора.
После подключения RPC прошли 59 профильных проверок, полный Windows-набор
из 1284 тестов с двумя прежними пропусками и десять независимых проверок
Backend и клиента. Независимый Spec review не нашёл дефектов; Standards review
не нашёл блокирующих замечаний и сохранил явный список небольшого технического
долга. Этот код находится в отдельном локальном экспортёре.

Одна живая попытка 2026-10-24 остановилась после census с причиной
`scope_calls`: нижняя оценка числа чтений трёх проходов превышала оставшийся
лимит вызовов. Census выдал 58 636 строк; адаптер записал 58 637 шагов
итератора. Его `calls = 1` обозначает вызов census, а не один системный запрос.
Запрошенных байтов содержимого и вызовов `ReadProcessMemory` было ноль.
Строки поиска, chunks и кандидаты не читались.

Вся последовательность — начальный `info`, поиск, повторный `info`, закрытие
и проверка файла — заняла около 0,47 секунды. Повторный `info` подтвердил,
что последовательный worker отвечает; затем получено
штатное подтверждение закрытия, файл ReaderSession исчез, дочерний процесс
диагностики завершился. Поиск не повторялся, scope не обрезался и лимиты
не повышались. Управление игрой не использовалось. Новый снимок, полный
импорт и точный DPS не получены; дальнейшая работа требует другого
проверенного способа укладки чтений или получения корневой ссылки.

## Офлайн-проверка одной ветки кэша

Внешний экспортёр также содержит отдельный проверенный `sample(reader, address)`.
Он наблюдает сырые поля `BeRealCache` и `SkillStoneId`, выбирает ровно один банк
и проходит путь `bank[typedStone]['A'][5109]`. Строковый и целочисленный ключи
различаются; подстановка другого банка или навыка не допускается. Наличие
этих данных по указанному адресу не доказывает выбор персонажа.

Профиль ограничен 1024 попытками чтения содержимого, 256 КиБ запрошенных
байтов, 32 различными таблицами, глубиной 5 и мягкой секундой. Допускаются
восемь присутствующих ключей кэша, 32 ячейки неглубоких листьев и 128 КиБ
выходного JSON. Непрозрачный лист сохраняет только тег; чтение по его
указателю не выполняется. Табличный лист рассматривается неглубоко, без обхода вложенных
таблиц и metatable. Неизвестное значение остаётся обозначенным неизвестным.

Два независимых наблюдения проверяют также структурные отрицательные исходы.
Предварительная оценка байтов учитывает повтор всего уже прочитанного
префикса; неизбежный перерасход вызывает отказ до чтения тела таблицы.
Итоговая проверка дедлайна охватывает и позднюю ошибку чтения. Пустая
выделенная часть массива не считается присутствующим ключом кэша; бинарный
строковый ключ навыка сохраняется точными байтами в приватной проекции.

Пять дефектов независимо воспроизведены до исправления. После исправлений
прошли 37 профильных тестов, полный Windows-набор из 1321 теста с двумя
прежними пропусками и 15 независимых проверок координатора. Независимый Spec
review завершён; независимый Standards review не нашёл блокирующих замечаний
после уточнения словаря типов, сохранив явный технический долг. Самопроверка
автора учитывается отдельно. Последняя правка docstring не изменила
исполняемый AST, что проверено отдельно без удаления вложенных docstring.

Это офлайн-модуль с прямым reader, без подключения к RPC или обычному
импорту. Обёртка над удалённым reader не доказывает такой же предел нативных
вызовов: транспорт может делить одно логическое чтение. Живого вызова этого
модуля не было; кэш может содержать нативные объекты, а не готовые скаляры.
Полный импорт и точный DPS Carino остаются неподтверждёнными.

## Планирование чтений без уменьшения области

Отдельный офлайн-планировщик проверяет все строки собранной карты до
построения интервалов. Он объединяет только точно смежные читаемые
`MEM_PRIVATE` строки. Объединение сохраняет тот же набор байтов; пропуски,
защищённые и другие исключённые строки не заполняются. Пределы обычного
reader не меняются. Проекция содержит количества и нижнюю оценку расходов,
без адресов; затраты на проверку кандидатов и соблюдение времени не доказаны.

В синтетическом примере 40000 смежных строк по 64 КиБ требуют 625 чтений
по 4 МиБ за проход вместо 40000. Полная смежность достаточна для этого числа,
но не необходима: два интервала, разделённые после первых 64 строк, также
могут требовать 625 чтений. Результат не измеряет смежность настоящей памяти.

Независимый review обнаружил сложение до ограничения операндов; дефект
воспроизведён до исправления. После исправления прошли 29 профильных тестов,
полный Windows-набор из 1350 тестов с двумя прежними пропусками и 14
независимых проверок координатора. На этом этапе планировщик ещё не был
подключён к поиску или RPC. Живое чтение этим блоком не выполнялось;
новый экспорт и DPS не получены.

Для следующей диагностики отдельно проверяется завершение обхода карты.
Остановка старого iterator сама по себе не доказывает достижение конца
адресного пространства. Предполагаемая постоянная граница не считается
наблюдением платформы; частичная карта не должна становиться полным планом.

Отдельная [строгая диагностика карты](strict-memory-census.md) уже проверена
офлайн: наблюдаемая граница платформы, явный отказ при раннем обрыве,
раздельные счётчики и ограниченная финализация каждого ответа. Живого
обхода при этой офлайн-приёмке ещё не было. Последующий живой результат
описан ниже; он не заменяет доказательство полноты будущей карты.

Следующий блок — [поиск v2 по смежным участкам](packed-memory-search.md) —
проверен офлайн: он использует планировщик для собственной прежней карты
без увеличения лимитов. Прошли 1405 тестов с двумя прежними пропусками,
194 профильных теста и 16 отдельных независимых проверок координатора.
Живой результат описан ниже; текущий персонаж пока не подтверждён.

Для следующего шага также проверен
[клиентский адаптер чтения кэша](remote-cache-reader.md): один ограниченный
запрос через существующий Reader, без дробления и повтора. Он пока не
подключён к обычному импорту и не подтверждает текущие значения персонажа.

[Маркеры кадра кэша](cache-frame-witness.md) сохраняются без дополнительных
чтений содержимого, с явными пропусками для неподдержанных типов.
[Поэтапный диагностический сценарий](staged-cache-acquisition.md) проверен
на искусственной цепочке поиска и чтения; этапы требуют отдельных решений,
а неопределённый RPC запрещает дальнейшие обращения и повтор той же записи.
Полная цепочка с чтением кэша и точный DPS пока не подтверждены.

[Первая живая проверка](live-packed-search.md) завершила диагностику карты,
но поиск v2 остановился на первом отказе чтения. Таблица не выбрана,
сессия закрыта, повторного сканирования не было.

[Диагностика первого пропуска v3](first-unread-diagnostic.md) теперь сохраняет
приватные координаты и закрытую категорию ошибки без дополнительных чтений.
Поздний сбой отклоняется по дедлайну; неполная область не получает цель.
Офлайн-проверка не объясняет прежний отказ и не разрешает повтор полного поиска.

[Три показателя из двух атрибутов](two-attribute-displays.md) связывают
точные аргументы getter с условными формулами источника. Один лист 5109
не заменяет атрибут 5727, вложенные множители и проверку актуальности.

[Срок жизни выбранного навыка](selected-skill-lifetime.md) уточняет индексное

не подтверждает активный выбор; контракт сохранённого кода не устанавливает
текущего владельца, доставку событий или атомарность.
