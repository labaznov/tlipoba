# Общий бюджет чтения при поиске билда

Проверено 2026-10-23 по коду отдельного Windows-экспортёра. Его обычный
`discover`, вызываемый через ReaderSession, теперь использует один общий бюджет
для чтений и перечисления регионов. Код экспортёра остаётся вне этого PR;
после изменения новая живая проверка не выполнялась.

Бюджет ставится перед первым census. В него входят chunk-проходы и вложенные
чтения `Inspector`, `read_exact` и `inspect_controller`. Запрос учитывается
до выполнения; ошибочное или короткое чтение остаётся учтённым. Превышение
не превращается в обычное отклонение кандидата: весь поиск завершается отказом.
Последняя проверка также запрещает вернуть результат, если внутренний обработчик
подавил исключение исчерпанного бюджета. Поэтому исчерпание при проверке второго
владельца не разрешает выбрать первого как единственного.

| Ограничение | Значение по умолчанию |
| --- | --- |
| Вызовы чтения и census вместе | 100000 |
| Выданные строки списка регионов | 65536; затем допускается одна проверка конца списка |
| Запрошенные байты | `3 × limit + 256 MiB` |
| Мягкий срок | `3 × seconds + 30` секунд |
| Один запрос чтения | Не более 4 MiB |

При прежних `limit=12 GiB` и `seconds=90` это 36.25 GiB запрошенных байтов
и мягкий срок 300 секунд. Значения выбраны как инженерные ограничения;
достаточность и скорость на живом процессе ещё не измерены. Deadline проверяется
между операциями и шагами census; уже выполняющийся системный вызов не прерывается.
Счётчики не являются измерением нагрузки CPU или объёма выделенной памяти.

Параметры проверяются до I/O и вычисления производных лимитов: `chunk_size`
от 128 байт до 4 MiB, `limit` от 1 байта до 64 GiB, `seconds` от 0.001 до 3600.
Требуются точные допустимые числовые типы; bool, нечисловые объекты, NaN,
бесконечности и неизвестные ключи отклоняются. Публичный `discover` не позволяет
передать частный `budget=`. Запросы не разбиваются скрыто на части.

Частный [cache-путь](cached-discovery.md) использует тот же бюджет после проверки
cache и параметров, до свежего census. Проверка исчерпания стоит перед успешным
результатом и обоими `stale`. Его метаданные теперь содержат
`quotaEnforced=true` и `quotaScope=this_discovery_call_reads_and_census_only`.
Неизвестные currentness и allocation identity сохраняются. Сам cache-путь
по-прежнему не подключён к обычному RPC или захвату.

Только граница RPC `Backend.dispatch(discover)` переводит отказ в фиксированный
текст `Discovery read budget exhausted: <reason>`, где причина — одно из
`calls`, `bytes`, `deadline`, `regions`, `request`. Клиент получает обычную ошибку,
а CLI завершается с кодом 1 до создания source, пакета и `latest.json`.
Автоматического повторного поиска нет.

Это бюджет одного поиска. `capture_controller`, `config_lookup`, последующие
операции и общий процесс экспорта им не ограничены. Таймаут клиента не отменяет
работу сервера. Полнота импорта, эффективный уровень, текущий персонаж,
атомарность снимка и точный DPS Carino этим не подтверждаются. Для будущей
живой проверки требуется обычный новый ReaderSession; горячая перезагрузка
и обход прав не предусмотрены.

Синтетические проверки внешнего проекта покрывают учёт до чтения, лимиты,
отказы при проверке второго владельца, изменившийся заголовок с чрезмерным
размером чтения и подавленное исключение перед возвратом cache-результата.
Полный Windows-набор: 784 теста, один пропущен из-за прав на symlink.
Отдельная проверка координатора прошла через настоящий путь
CLI → `capture_open` → `RemoteReader` → обмен → обработчик RPC → поиск,
заменив только транспорт соединения на синтетический. При одном разрешённом
census и нуле чтений получены фиксированная ошибка, код 1 и отсутствие выходных
файлов; все синтетические соединения закрыты. Проверка предыдущей RPC-границы
выполнена после реализации, с восстановленным и сверенным по SHA исходником;
это не исходный цикл TDD и не проверка живого IPC или аутентификации.
