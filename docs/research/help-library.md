# Реестр игровой справки SS14

Проверено 2026-10-21. [Исходный индекс TLIDB Help](https://tlidb.com/en/Help) содержит 215 записей Help и 72 Handbook: 287 вхождений, 263 уникальных URL. [Машинный реестр](../../damage_lab/data/help-index-ss14.json) сохраняет все вхождения, названия, исходные вкладки, позиции, даты и статус чтения.

`index_discovered` означает только найденную ссылку. `body_reviewed` означает прочтение перечисленных `reviewSections` с собственным кратким выводом; это не утверждение о проверке всех каталогов предметов на том же URL. `blocked` означает, что тело получить не удалось. Повторный URL не удаляет его второе название или положение в индексе. Категории `Help` и `Help_Handbook` взяты из вкладок источника; смысловые категории игры не выдуманы.

Проверены все 263 адреса: доступное тело прочитано для 261, два остаются `blocked`. Все 215 вхождений Help имеют прочитанный источник; у Handbook это 70 из 72. У [Hero Relic](https://tlidb.com/en/Hero_Relic) получен пустой ответ 404; у [Hero Memories](https://tlidb.com/en/Hero_Memories) доступны таблицы, но отсутствует искомое тело Help. Это пробелы источника, а не изученные статьи. Счётчики разделов учитывают вхождения уже прочитанного URL, а не независимые повторные чтения.

TLIDB — неофициальное зеркало игровых текстов и датамайна. Сам сайт предупреждает об отличиях от релизной игры. SS14 здесь обозначает рабочий снимок проекта, а не подтверждённую версию каждого старого абзаца. Разные одноимённые разделы URL могут описывать разные механики; `Replicate`, `Beacon` и `Boss` особенно требуют проверки раздела. Доступные исходный HTML, текстовые ответы инструмента, срезы и журналы получения хранятся в игнорируемых локальных данных; публично остаются ссылки, собственные краткие выводы и формулы.

`body_reviewed` фиксирует историческое чтение раздела; это не гарантия наличия локальных байтов полного тела. Офлайн-инвентаризация 2026-10-22 отдельно связала проверенные файлы и собственные Help-разделы с хешами и координатами. Упоминание URL в навигации, таблица каталога и review summary не заменяют тело статьи. Хеш сохранённого ответа web-tool подтверждает именно это представление, а не оригинальные сетевые байты. При использовании формулы в resolver нужно проверить соответствующий абзац и его применимость; прочитанный текст не подтверждает runtime или версию клиента.

## Проверенные расчётные области

[Формулы дропа](help-loot-formulas.md) отделяют ожидаемое количество от распределения случайных результатов, дополнительных предметов и качества. Базовые таблицы вероятностей, цены наград и полный доход за карту не восстановлены. Наличие записи в библиотеке не означает поддержку её расчёта в коде.

Реализован [условный расчёт дропа](../LOOT.md): quantity → дополнительные предметы → одновременная конверсия → гарантированные копии. Число слотов или наборов не подменяется неизвестным числом предметов внутри набора. Остальные формулы справки пока являются знаниями с источником, а не исполняемыми выражениями.

## Локальный поиск и обновление

```powershell
python -m damage_lab.helpbook search "drop"
python -m damage_lab.helpbook search "Critical Strike"
python -m damage_lab.helpbook merge --index damage_lab/data/help-index-ss14.json --review docs/research/help-main-1-37.json --output local-data/updated-help.json
```

Поиск работает без сети по названиям, выводам и формулам. Краткая карточка содержит один детерминированно выбранный обзор; остальные выводы остаются в `reviewHistory` и также доступны поиску. Формулы и неизвестные объединены с сохранением вариантов. Слияние требует новый выходной файл, сохраняет позиции исходного индекса и историю обзоров; конфликтующие сведения не получают статус истины из-за даты чтения. `body_reviewed` сильнее неудачной попытки получения того же текста. Это правило покрытия, не выбора игровой версии.

[Hunter file](https://tlidb.com/en/Hunter_file#Hunterfile-Help) предупреждает, что профиль обновляется с задержкой: свежая смена экипировки может быть ещё не видна. Это основание хранить время и происхождение импорта; статья не раскрывает API или интервал обновления. [Generate Build Code](https://tlidb.com/en/Generate_Build_Code) подтверждает загрузку текущего билда ради кода, а [Use Build Code](https://tlidb.com/en/Use_Build_Code) — получение подсказок по чужому коду. Полнота, формат и доступность endpoint из этих статей не следуют.

## Противоречия и неизвестные

- [Character Build](https://tlidb.com/en/Character_Build) расходится с отдельными статьями: сопротивление 75%/95% вместо [60%/90%](https://tlidb.com/en/Resistance); блок 35%/75% вместо [30% и пределов 60%/80%](https://tlidb.com/en/Block); точность монстра 1247 вместо [диапазона 130–680](https://tlidb.com/en/Evade); предел Affliction 50% вместо [100%](https://tlidb.com/en/Amplified_Damage_Over_Time). Ни один вариант не выбран автоматически по времени обхода сайта.
- [Psalms of Aeterna](https://tlidb.com/en/Psalms_of_Aeterna) одновременно содержит коллективный сброс до уровня 1 с частичным возвратом и отдельный Handbook-текст о полном возврате для большинства узлов. Применимая версия не выбрана.
- [Timemark](https://tlidb.com/en/Timemark) называет для Timemark 8 три Offset Degrees и перечисляет 0–3. Это сохранено как внутренняя несогласованность.
- [Memory Revival](https://tlidb.com/en/Memory_Revival) явно ограничивает число попыток; предел роста стоимости рассматривается отдельно. Числовые пределы, шансы и стоимость ещё не установлены для расчёта.
- Исторические exclusive-source утверждения о предметах не становятся доказанными ограничениями текущего релиза только из-за сегодняшней доступности страницы.
- Неприведённая вероятность, порядок или округление остаются `unknowns`; измеренный DPS и пользовательские показатели для заполнения пробелов не используются.
