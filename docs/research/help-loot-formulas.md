# Формулы дропа из Help

Проверено 2026-10-21 для библиотеки проекта SS14. Источник — игровые Help-тексты в неофициальном зеркале TLIDB; версия отдельных абзацев не закреплена за релизом. Формулы ниже описывают свою область, а не полный доход с карты. Все проценты в выражениях представлены долями.

## Порядок и ожидаемое количество

[Effect Priority](https://tlidb.com/en/Effect_Priority) задаёт последовательность: общие quantity/additional quantity/rarity → quantity соответствующего типа → дополнительные предметы → конверсия типа → репликация. Внутренний порядок первой группы не уточнён.

[Drop quantity, ManualRule](https://tlidb.com/en/Drop_quantity#DropquantityManualRule): для подходящего базового дропа `Ebase = E0 × (1 + Σq) × Π(1 + m)`. Обычные quantity складываются, отдельные additional quantity образуют множители; соответствие конкретных аффиксов этим входам ещё нужно проверять. Веса предметов таблицы не меняются. Среди исключений названы Cube rewards, Dream Bubbles, Folklore chests и Splendor Eggs. Это формула ожидания, не целочисленное округление результата.

[Quantity конкретного типа](https://tlidb.com/en/Drop_Quantity_Bonuses_for_Certain_Item_Types): `Etype = Ebase × (1 + Σt)` только для исходного подходящего типа; веса внутри типа сохраняются. Help прямо показывает суммирование этого пула, несмотря на встречающееся слово additional в названиях. Его нельзя автоматически заменять правилами more боевого урона.

Распределения двух стадий различаются: общий quantity +100% для исходного шанса .5 на один предмет даёт `P(0,1,2)=(.25,.5,.25)`; типовой +100% сохраняет `.5` вероятности пустого исхода и удваивает количество при успехе. Типовой пример +50% и +25% даёт один предмет с вероятностью .25 и два с .75. Это опубликованные примеры; универсальный алгоритм дробных попыток или округления не выведен.

## Дополнительные предметы, качество, конверсия

[Additional Drops](https://tlidb.com/en/Additional_Drops) минуют все quantity, additional quantity, rarity и type quantity, но участвуют в последующих конверсии и репликации. Они срабатывают только у монстров, способных вообще давать предметы. Для одного явно заданного триггера с шансом `p` и фиксированным количеством `n` математическое ожидание `p×n` — арифметическое следствие; сами параметры нужно получить из аффикса.

[Drop rarity](https://tlidb.com/en/Drop_rarity#DroprarityManualRule) влияет на качество экипировки и Hero Memories; предметы, порождённые аффиксами, исключены. Формула вероятностей качества и числовые веса не приведены. [Reward](https://tlidb.com/en/Reward) перечисляет пять уровней наград, но не их шансы.

[Type Conversion](https://tlidb.com/en/Type_Conversion) применяется после всех quantity-бонусов. Исходный gear quantity может увеличить число конвертируемых предметов; destination Fuel quantity повторно не применяется. При суммарном competing conversion chance выше 100% шансы нормируются пропорционально. Для одного исходного типа это можно записать как `pᵢ / max(1, Σp)`; остаток при сумме ниже 1 — вывод из вероятностной интерпретации, а не отдельная приведённая формула. Конверсия может дать набор с разным количеством предметов; состав и веса неизвестны.

## Репликация и ограничения

[Replicate, ManualRule](https://tlidb.com/en/Replicate#ReplicateManualRule) различает обычные и дополнительные повторения: внутри класса числа копий складываются, между классами множатся. Для гарантированных срабатываний `copies=(1+Σr)×(1+Σa)`; пример Help даёт `(1+1+2)×(1+1)=8`. Вероятностные срабатывания, условные зависимости и точный момент их проверки требуют отдельных аффиксов. Копирование плит, монстров и Dream Bubbles на том же URL — другие области.

Без базовых вероятностей, списка подходящих источников, точных аффиксов и состава наборов допустим только условный расчёт ожидания. Не следует симулировать неизвестные таблицы, переносить бонусы на исключённые награды или вычислять точный доход за карту.
