# Hero Memories: повышение ранга свойства и границы вывода

Проверено 2026-10-21 для импортёра SS14. Исследованы опубликованные игровые Help/каталоги TLIDB и официальные патчноуты; процесс игры и UI не читались. Показатели, идентификаторы и захваты персонажа не публикуются.

## Вердикт

Источники подтверждают существование прибавок Trait Level от усиления и fixed affix. Они **не устанавливают точное соответствие внутренних полей** `ReminiscenceFixedLevel` / `ReminiscenceFixedLevelFromEnhance` итоговому рангу. Поэтому `clientFixed + fromEnhance` остаётся обоснованным кандидатом, а не подтверждённой формулой SS14.

Один уровень воспоминания не доказывает выполненное повышение ранга: Help различает Enhancement Level и апгрейд Trait Level с дополнительными материалами. Подстановка `1 + [level≥30] + [level≥50]` без проверки состояния апгрейдов не следует из этой справки. [Memory Upgrade](https://tlidb.com/en/Memory_Upgrade).

## Кандидаты для внутреннего адаптера

Обозначения относятся к входной гипотезе импортёра, а не к подтверждённой схеме игры:

- `C` — клиентское `ReminiscenceFixedLevel`
- `S` — серверское одноимённое поле
- `E` — `ReminiscenceFixedLevelFromEnhance`
- `F` — сумма подтверждённых fixed affix прибавок Trait Level
- `L` — Enhancement Level, если отдельно доказано соответствие `ReminiscenceLevel`

| Кандидат | Статус после проверки |
| --- | --- |
| `C = S + F` | Неподтверждённая каталожная гипотеза; контракт импортёра `0.1.1` не использует её как проверку согласованности. Публичный текст подтверждает существование `F`, но не семантику `C` и `S` |
| `rank = C` | Не исключён источниками: неизвестно, включает ли `C` enhancement contribution |
| `rank = C + E` | Согласуется с раздельными источниками прибавок; требуется доказать, что `E` аддитивен и ещё не включён в `C` |
| `rank = 1 + [L≥30] + [L≥50] + F` | Требует подтверждения исходного ранга, актуальных порогов и факта выполнения апгрейдов; одного достижения `L` недостаточно для доказательства |

Help описывает бонусы игровыми терминами; он не называет ни одно из этих native-полей. Имена полей и совпадение стороннего планировщика не заменяют контракт. Если `C` уже содержит `F`, формула `C + E + F` посчитает fixed affix дважды.

## Конкретный оставшийся пробел

Нужен версионированный первичный источник, который связывает итоговый Trait Level с `C` и `E`: например, клиентская функция вычисления ранга либо сохранённая модель tooltip с итоговым рангом и теми же memory-полями. Для различения кандидатов достаточно состояния с ненулевым `E`, проверенной связью памяти с выбранным свойством и явным итоговым рангом. Никакое число DPS для этого не требуется.

Для базового свойства отдельно нужны подтверждение активного Base Trait Slot, помещённой в него памяти и mapping слота. Отсутствие памяти в одном наблюдаемом контейнере не доказывает автоматически ни ранг 1, ни отсутствие прочих источников ранга.

До получения доказательства адаптер может сохранять входные поля и именованные кандидаты с `rank_rule_unverified`; правило не выбирается по умолчанию. Каталожные ранги используются только при установленном источнике выбора, а неизвестный ранг остаётся пробелом. Повышение уровня свойства и +50% Heat Up Effect — разные операции; их нельзя подменять друг другом или выбирать по совпадению с манекеном.
