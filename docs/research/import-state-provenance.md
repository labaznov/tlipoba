# Состав билда и фактическое состояние расчёта

Проверено 2026-10-22 по уже сохранённым файлам экспортёра, журнала и каталогов. Нового обращения к игре не было. Частные значения персонажа и идентификаторы экземпляров остаются локальными.

## Что установили

Клиентский SkillLayout, серверные слоты и ссылка guide на тот же экземпляр подтверждают установку поддержки в группе Chromatic Shot. Перемещение этого экземпляра из слота и обратно подтверждено событиями журнала. Однако эти свидетельства относятся к разным моментам: состав старого экспорта не становится свежим боевым состоянием по совпадению номера слота.

Флаги `Valid`, `IsActive`, `Energy`, `CostState` и `UnlockState` одинаковы у всех установленных строк трёх сохранённых снимков. Без первичного определения полей или состояния с проверенно выключенной поддержкой они не подтверждают её активацию. Уровень самого гема не доказывает эффективный уровень с учётом всех источников. `RoleAttrMgr` не называет навык показанной панели.

Поэтому автоматический импорт должен различать установку, активацию, эффективный уровень и идентичность навыка панели. Последние три поля остаются неизвестными; неизменность чисел после снятия поддержки не доказывает отсутствие её эффекта в попаданиях. [Описание контрольных опытов](panel-formula-evidence.md) сохраняет эти границы.

## Основные атрибуты

Отдельные статьи [Strength](https://tlidb.com/en/Strength), [Dexterity](https://tlidb.com/en/Dexterity) и [Intelligence](https://tlidb.com/en/Intelligence) описывают 0.5% дополнительного урона за пункт соответствующего основного атрибута; подходящие атрибуты складываются до общего множителя. Для навыка с тремя main-stat тегами кандидат формулы — `1 + 0.005 × (Strength + Dexterity + Intelligence)`.

Именованных итогов этих атрибутов в сохранённых данных не найдено. Числовые stat ID не сопоставлены с названиями. Частичные суммы аффиксов предметов не заменяют итог: отсутствуют проверенные вклады базы героя, роста, талантов, плит и процентных бонусов. Подбирать сопоставление по совпадению DPS нельзя.

Контроль Lightchaser показал изменение внутри готового Additional Damage Bonus. При расчёте от панели атрибутный множитель повторно не применяется. Формула с нуля потребует независимо установленных значений и привязок; совместимость гипотезы с одной парой не подтверждает её.

## Следующие проверяемые границы

- Для рангов героя нужны значения, различающие правила `C` и `C + E`; текущий импорт сохраняет оба кандидата и `rank = null`
- Для атрибутов нужна именованная схема stat ID либо именованный итог того же состояния
- Для поддержки нужны проверенные семантика активации и источники эффективного уровня
- Для панели нужна явная привязка к навыку, состоянию и моменту снимка

Это задачи адаптера и модели. Ручная анкета игрока не считается их решением; неизвестные данные не превращаются в коэффициент для совпадения с манекеном.
