# Сезон и достоверность параметров

Исследование 2026-10-21 определило правила для дальнейших адаптеров данных. Они не требуют переносить сторонний каталог в публичный репозиторий.

1. Каждая запись хранит сезон, числовой ID, источник, дату получения и SHA-256 исходных байтов. Токен версии сайта сохраняется отдельно: он не считается контрольной суммой
2. Результат одного расчёта относится к одному сезону; автоматической подстановки старого сезона нет
3. Числа берутся из конкретной строки уровня и её параметров. Текст, уже отрисованный на другом уровне, не определяет значения
4. Повторяющийся хвост таблицы проверяется для каждого навыка отдельно. Неизвестные значения не продолжаются линейно и не копируются с предыдущего уровня
5. Совпадение сайтов с общим upstream не считается двумя независимыми измерениями
6. Сохранённые снимки дополняются новыми версиями без перезаписи; конфликт источников хранится вместе с кандидатами и причиной выбора
7. Парсеры тестируются на синтетических локальных файлах в Windows. Сеть, игровые захваты и GitHub runners не нужны для таких тестов

Для Chromatic Shot текущая таблица повторяет урон уровня 20 в строках 21–40, а эффективность добавленного урона в этом хвосте не определена. Эти строки остаются непроверенными. Это не универсальное ограничение саппортов: их таблицы проверяются отдельно. [Chromatic Shot](https://tlidb.com/en/Chromatic_Shot).

Уточнение по Help: плоская база после 20 может быть намеренной, если дальнейший рост задаёт отдельный множитель уровня. Пустой хвост нельзя приравнивать к отсутствию роста итогового урона; конфликтующие профили описаны в [проверке Skill Level](help-skill-levels.md).

Официальные изменения дают контрольные значения, но не заменяют полную таблицу уровней. Для SS14 приоритет имеет дополнение к патчноутам, если оно изменяет прежнее описание. [Официальные изменения SS14](https://torchlight.xd.com/ss14pn/?lang=en).

Ближайший адаптер должен читать одну сохранённую страницу, разрешать её ID/сезон/строки, отмечать подозрительный хвост и сохранять происхождение каждого числа. Результат парсинга отделён от решения о подтверждении значения и от расчётного ядра.
