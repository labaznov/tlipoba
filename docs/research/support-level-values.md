# Значения саппортов и уровни

Проверено 2026-10-21. Исследование внешнего экспортёра обнаружило, что готовое описание саппорта может содержать числа первого уровня, хотя рядом записан другой уровень камня. Такие числа нельзя использовать как параметры расчёта.

Два независимо проверенных примера SS14:

| Саппорт | ID | Уровень 1 | Уровень 20 | Семантика |
| --- | --- | --- | --- | --- |
| Critical Strike Damage Increase | 7420 | 26% | 35,5% | Дополнительный урон только критического попадания |
| Multiple Projectiles | 7401 | 7,4% | 15% | Дополнительный урон поддерживаемого навыка; отдельно +2 снаряда |

Числа взяты из отдельных строк таблиц, а не экстраполированы. [Critical Strike Damage Increase](https://tlidb.com/en/Critical_Strike_Damage_Increase), [Multiple Projectiles](https://tlidb.com/en/Multiple_Projectiles).

Вход движка должен хранить ID навыка, фактический уровень, поле таблицы, разрешённое числовое значение и источник. Ячейки вроде `37/5` означают рациональное число; произвольные выражения не выполняются. Отсутствующая строка, неизвестная привязка параметра или неоднозначный уровень остаются пробелом, а не выбирают первый уровень.

Для крита `E = (1−p) + p × critical_multiplier × (1+critical_only_more)`. При Lucky используется `p_eff = 1−(1−p)²`, только если Lucky ещё не учтён. Более точное значение саппорта меняет проверку согласованности панели; одно совпадение с округлённым DPS не доказывает семантику панели и не разрешает автоматически добавить Lucky. Контрольный игровой замер не служит множителем.

Новый импорт должен переносить разрешённые параметры из пакета. До исправления экспортёра старые descriptions остаются описательным материалом, а не числовой моделью полного билда.
