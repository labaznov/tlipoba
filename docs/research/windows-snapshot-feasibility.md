# Windows Process Snapshotting: предварительная оценка

Проверено по документации Microsoft 24 октября 2026 года. Это исследование,
а не реализованный адаптер: PSS, клонирование, приостановка, дамп и новые права
доступа к игре не применялись. Причина ранее наблюдавшейся ошибки чтения остаётся
неизвестной.

## Что подтверждено документацией

`PssCaptureSnapshot` принимает handle процесса, флаги и возвращает отдельный
handle снимка; успешный результат — `ERROR_SUCCESS`. Минимальная версия клиента
в документации — Windows 8.1 для desktop apps. Страница функции не задаёт полный
набор необходимых прав для каждого сочетания флагов.
[PssCaptureSnapshot](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/nf-processsnapshot-psscapturesnapshot).

`PSS_CAPTURE_VA_CLONE` включает клонируемые страницы: `MEM_PRIVATE` и разделяемые
секции `MEM_MAPPED`/`MEM_IMAGE`. `PSS_CAPTURE_VA_SPACE` сохраняет карту
`MEMORY_BASIC_INFORMATION` без содержимого страниц. Эти режимы нельзя считать
одинаковыми способами получения данных. Отдельный флаг измерения производительности
предусматривает получение счётчиков; численной оценки затрат для нашей задачи
страница не даёт. Флаги breakaway меняют отношение клона к job, а принудительный
вариант требует Tcb privilege; такие флаги не входят в предлагаемый эксперимент.
[PSS_CAPTURE_FLAGS](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/ne-processsnapshot-pss_capture_flags).

`PssQuerySnapshot` получает сведения выбранного класса в буфер заданной длины;
неверная длина, handle, класс или отсутствие данных имеют отдельные результаты.
Для `PSS_QUERY_VA_CLONE_INFORMATION` структура содержит `VaCloneHandle` — handle
процесса клона. Это не готовая сериализация персонажа.
[PssQuerySnapshot](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/nf-processsnapshot-pssquerysnapshot),
[PSS_VA_CLONE_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/ns-processsnapshot-pss_va_clone_information).

`PssFreeSnapshot` требует различать процесс, которому принадлежит descriptor
снимка, и исходный процесс. Для локально захваченного или локально дублированного
снимка документация указывает `GetCurrentProcess`; при удалённом освобождении
описывает дополнительные права и ограничения. Повторное освобождение уже
освобождённого descriptor имеет неопределённое поведение; конкурентный доступ
сам API не защищает. Нельзя автоматически приписывать права удалённого
освобождения handle исходной игры.
[PssFreeSnapshot](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/nf-processsnapshot-pssfreesnapshot).

Обычный `ReadProcessMemory` требует `PROCESS_VM_READ`; недоступная часть
запрошенного диапазона приводит к отказу. Наличие доступной карты в другой момент
не устанавливает причину конкретного отказа и не заменяет число фактически
переданных байтов.
[ReadProcessMemory](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory).

## Что остаётся неизвестным

В проверенных страницах не найдено полного контракта минимальных прав capture
для VA clone. В частности, необходимость `PROCESS_CREATE_PROCESS` здесь
не подтверждена первичным источником; не переносим её из сторонних примеров.
Точные задержка, память, влияние на работающую игру, ограничения конкретной
архитектуры и жизненный цикл возвращённого clone handle требуют отдельной проверки.

Документы не доказывают согласованность предметных структур приложения:
снимок может сохранить промежуточное состояние обновления объекта. Он также
не доказывает выбор текущего персонажа, полноту данных или свежесть панели.
Это ограничения нашего вывода, а не утверждение о внутренней реализации PSS.

## Решение

Для адаптера игры PSS пока не принят. Сначала завершаем отдельную диагностику
точного диапазона существующим read/query API. Разрешение пассивно читать память
не считается разрешением клонировать игру или запрашивать дополнительные права.

Возможный будущий эксперимент ограничивается собственным синтетическим процессом:
один небольшой известный буфер, один снимок, сравнение до/после изменения буфера,
запись времени и ресурсов. Перед запуском нужно установить контракт прав,
владения clone handle и освобождения ресурсов. Затем проверить все ветви отказа,
однократное освобождение, завершение собственного процесса и внешнюю границу
ожидания. Пока этот контракт неизвестен, эксперимент не запускается и не выдаётся
за готовый способ импорта.
