# Пассивное наблюдение транспорта игры в Windows

Проверено 2026-10-22 по официальной документации. Координатор проверил наличие инструментов через `Get-Command` и синтаксис только через `pktmon start help` / `pktmon filter add help`: нужные параметры доступны на хосте. **Реальный захват не проверен.** При подготовке этой заметки не выполнялись capture, запросы процессов/соединений или изменения настроек.

Цель будущего опыта — связать одно действие интерфейса с PID, сокетом, удалённым адресом и временным окном. Это шаг к [импорту по коду](build-import-api.md), а не готовый загрузчик: [существующая привязка сохранённых данных](build-resolution-evidence.md) пока не устанавливает сетевой контракт.

## 1. Сначала только метаданные сокетов

При доступном разрешённом живом наблюдении выбрать PID известного экземпляра игры в Task Manager. Записать PID, время старта процесса и UTC; PID может использоваться повторно. Число ниже **вымышленное**, подставлять его без проверки нельзя.

```powershell
$gamepid = 12345
[DateTimeOffset]::UtcNow.ToString('o')
Get-NetTCPConnection -OwningProcess $gamepid |
    Select-Object CreationTime,LocalAddress,LocalPort,RemoteAddress,RemotePort,State,OwningProcess
Get-NetUDPEndpoint -OwningProcess $gamepid |
    Select-Object CreationTime,LocalAddress,LocalPort,OwningProcess
```

Повторить снимок непосредственно до и после действия. TCP показывает удалённую пару; UDP здесь даёт привязанный локальный сокет, не доказанного удалённого партнёра. Это моментальные таблицы: короткие соединения могут быть пропущены. Не распространять PID игры на соединения других процессов. [Microsoft: TCP](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection?view=windowsserver2025-ps#description), [UDP](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-netudpendpoint#syntax)

## 2. При необходимости — короткий фильтрованный Pktmon

Pktmon встроен в Windows; установка другого инструмента не требуется. Для системного захвата планируется отдельная повышенная консоль, без повышения прав игры. Отклонённое разрешение не обходить изменением политики. [Microsoft: Pktmon](https://learn.microsoft.com/en-us/windows-server/networking/technologies/pktmon/pktmon), [процедура системной сетевой трассировки](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/tcpip-performance-known-issues#steps-to-take-logs-with-network-packet-capturing-tools)

Перед будущим запуском проверить состояние и фильтры:

```powershell
pktmon status
if ($LASTEXITCODE -ne 0) { throw 'Не удалось проверить состояние Pktmon' }
pktmon filter list
if ($LASTEXITCODE -ne 0) { throw 'Не удалось проверить фильтры Pktmon' }
```

Если уже идёт захват, есть чужие фильтры или вывод нельзя уверенно прочитать, **остановиться без их изменения**. Согласовать исключительное владение сессией на время опыта; не останавливать чужую диагностику. Проверки не резервируют Pktmon атомарно: если нельзя исключить параллельное управление, этот пример не запускать. Создать новый приватный каталог под ignored `local-data`, проверить его исключение из Git. Каталог и все имена файлов должны быть новыми; существующие артефакты сохранять.

Фильтр строить только из фактически наблюдённого сокета. Здесь адрес `192.0.2.1`, порты и путь — **вымышленные placeholders**, не игровые endpoints:

```powershell
$directory = 'C:\Repos\tlipoba\local-data\transport-YYYYMMDD-HHMMSS'
New-Item -ItemType Directory -Path $directory -ErrorAction Stop
pktmon filter add GameTrial -i 192.0.2.1 -t TCP -p 43219 443
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить фильтр захвата' }
pktmon filter list
if ($LASTEXITCODE -ne 0) { throw 'Не удалось подтвердить фильтр захвата' }
```

**Граница перед start:** оператор должен проверить успешный вывод list: ровно один собственный `GameTrial`, ожидаемые протокол, адрес и оба порта из наблюдённого tuple. Неизвестный вывод, отсутствие условия или любой лишний фильтр означают **не запускать capture**. Это явная ручная проверка таблицы фильтров, не реализованный locale-независимый parser; нулевой exit code сам по себе её не заменяет. После любой ошибки не переходить к следующему блоку.

Условия одного фильтра соединяются AND; два порта должны присутствовать оба, направление не различается. Для UDP без установленного peer допустим более слабый фильтр `-t UDP -p <observed-local-port>` с явной неоднозначностью. Pktmon не фильтрует по PID: сопоставление с таблицей сокетов остаётся отдельным доказательством. Новый peer будет пропущен старым фильтром. [Microsoft: точная грамматика и семантика](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/pktmon-filter-add)

Один запуск — одно действие, не более 30 секунд нормального выполнения:

```powershell
$started = $false
try {
    pktmon start --capture --comp nics --pkt-size 128 --file-size 32 --log-mode circular --file-name "$directory\build.etl"
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось начать захват' }
    $started = $true
    Start-Sleep -Seconds 30
}
finally {
    if ($started) {
        pktmon stop
        if ($LASTEXITCODE -ne 0) { throw 'Не удалось подтвердить остановку своего захвата' }
    }
}
```

После успешного старта выполнить заранее подготовленное действие в другом окне. Сохранить вывод start/stop, ошибки и сведения о потерях. При ошибке start флаг остаётся false и stop не вызывается. `$started` — локальное свидетельство успеха, не системный handle владения: `finally` безопасен только при сохранении согласованного исключительного управления. Если сессию сменил другой участник, не применять к ней stop. Принудительное завершение консоли/системы может помешать cleanup; ошибку stop нельзя считать подтверждением остановки или разрешением конвертации.

Параметры означают NIC-компоненты, первые 128 байт каждого пакета и номинальный круговой ETL 32 MB. Круговой файл может потерять начало; заполненный лимит или потери запрещают заявлять полноту. Лимит ETL не является общей гарантией размера памяти и производных файлов; заранее оставить место, записать фактические размеры. Не использовать неограниченный multi-file. [Microsoft: start, размер пакета и режимы](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/pktmon-start)

**128 байт могут содержать часть payload: это уже не metadata-only.** Для полного пакета существует `--pkt-size 0`, но он здесь не выбран. Сокетные таблицы из шага 1 — отдельный режим без захвата содержимого.

Преобразование остановленного файла выполняется офлайн в новый файл:

```powershell
pktmon etl2pcap "$directory\build.etl" --out "$directory\build.pcapng"
if ($LASTEXITCODE -ne 0) { throw 'Не удалось преобразовать сохранённый захват' }
```

Сохранить исходный ETL, SHA-256 успешно созданных файлов и точные размеры. Конвертация не расшифровывает TLS. Удаление фильтров `pktmon filter remove` удаляет **все** фильтры: допустимо лишь после успешного list и повторной проверки, что исходно пустой набор содержит только собственный `GameTrial`. При чужих изменениях ничего не удалять; после remove проверить exit code и новым успешным list подтвердить пустой набор. Ошибка оставляет состояние неизвестным, не даёт права повторять очистку вслепую. [Microsoft: конвертация](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/pktmon-etl2pcap), [управление фильтрами](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/pktmon-filter)

## 3. Два отдельных контролируемых опыта

1. **Билд:** 5 секунд без действий → отметка UTC → открыть один разрешённый код через обычный интерфейс → записать время успеха/ошибки → автоматический stop. Не редактировать и не публиковать билд.
2. **Рынок:** другой новый каталог/файл, с повторной проверкой сокетов и фильтров; 5 секунд без действий → отметка UTC → один обычный поисковый запрос → время результата/ошибки → stop. Не покупать, не выставлять предмет и не запускать цикл обновлений.

Код, параметры поиска и идентификаторы сохранять только приватно; в публичной заметке достаточно обозначений Trial A/B. Сопоставлять PID в том же времени жизни, локальный сокет, tuple, направление, время и размеры пакетов. Сохранить также клиентскую версию/регион как наблюдённые сведения, а не вывод из адреса.

Всплеск после клика — кандидат корреляции. Соединение может обслуживать heartbeats, retries, несколько запросов или кеш; TCP ACK не является ответом RPC. Если передача не обнаружена, это ограниченный отрицательный результат данного фильтра/окна, не доказательство отсутствия API. Для доказанного запроса нужны декодированный envelope, операция, ключ корреляции, связь с входным кодом/поиском и форма ответа.

## Граница расшифровки и офлайн-анализа

TLS скрывает содержимое приложения; Wireshark требует подходящих секретов для расшифровки. Follow TCP Stream восстанавливает поток транспортных байтов, а не автоматически его шифрование или границы RPC. Эта процедура не получает секреты и не меняет запуск игры. [Wireshark: TLS](https://wiki.wireshark.org/TLS#tls-decryption), [Follow Stream](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvFollowStreamSection.html)

UDP не означает QUIC. У IETF QUIC часть Initial-handshake доступна через публично выводимые initial keys, но это не раскрывает защищённые application payloads. Нельзя по одному порту объявить QUIC, HTTP/3 или схему игры. [RFC 9001, раздел 5](https://www.rfc-editor.org/rfc/rfc9001.html#section-5)

В уже установленном Wireshark/TShark читать сохранённый файл офлайн; `-r` выбирает файл, `-n` отключает разрешение имён. Выводить только выбранные поля времени/адресов/портов/размеров, не полный hex/payload. Установку не выполнять ради этого плана. [TShark: параметры](https://www.wireshark.org/docs/man-pages/tshark.html)

Уже предоставленный HAR/SAZ можно анализировать как сохранённые данные без replay. HAR не появляется из зашифрованного pcap автоматически и может содержать cookies, Authorization, коды и приватные ответы. Сам факт поддержки формата не доказывает, что игра его экспортирует. [Fiddler: импорт сохранённых форматов](https://www.telerik.com/fiddler/fiddler-everywhere/documentation/collaboration/exporting-and-importing)

Будущий декодер допустим только для доказанного framing с точными offsets/stream/direction, контролем неполноты и ограничениями размера/глубины. Не подбирать endpoint, не воспроизводить авторизованные запросы и не перебирать JSON/protobuf/compression до правдоподобного результата. Неизвестные encrypted bytes остаются opaque.

Все оригиналы приватны и исключены из Git: захват может затронуть другие приложения, адреса и открытые данные. Не загружать raw traces или секреты на сторонние сервисы. Публиковать только минимальный обезличенный вывод с границами эксперимента. Результат этого плана — атрибуция транспорта либо честный encrypted/ambiguous gap; полнота билда, идентичность ответа и свежесть требуют отдельных свидетельств.
